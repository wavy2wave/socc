## Что строим (definition)
Entity Substrate is the next lawful substrate layer constructed by SOCC self-construction. It prepares persistent entity identity, state, memory, lineage, capability binding, dashboard visibility, lawful action boundaries, freeze/review/stop, and proof-chain for future entities such as Anna MVP.

## Основная линия
**Что это (одной фразой).** Entity Substrate — это «матрица рождения сущностей»: законный слой SOCC,
который даёт будущим цифровым сущностям (первая — ANNA, ассистент-администратор для стоматологий)
постоянную идентичность, состояние, память, происхождение (lineage), привязку способностей,
границы законного действия, видимость в дашборде, proof-цепочку и механизм freeze/review/stop.
Это **мост** от доказанной авто-самосборки SOCC к конкретному продукту.

**Чем НЕ является.** Не AGI-заявление, не чат-бот, не демон, не бесконечный цикл. Это инфраструктура,
которую SOCC строит сам по дисциплине самосборки — без ручного «handwave», без заявлений о живости
до появления runtime-доказательств.

**Программная цепочка (порядок строительства).**
`SOCC autonomous self-construction (✅ запечатан)` → `Entity Substrate (в процессе)` →
`ANNA MVP (только ПОСЛЕ печати Substrate)`. Ключевое различие, закреплённое каноном:
**ANNA = entity/product, а НЕ орган SOCC.** SOCC — суверенное ядро, которое *рождает* сущностей;
ANNA — первая такая сущность.

**Десять обязательных поверхностей (что Substrate обязан дать каждой сущности).**
identity · state · memory · lineage · capability_binding · lawful_action · dashboard ·
proof_chain · freeze/review/stop · anna_mvp_product_binding.

**Где мы сейчас (фактический статус цепочки на 2026-06-10).**
direction ✅ ACCEPTED → construction plan ✅ reviewed → scientific gate ✅ PASS →
Hermes gate ✅ PASS → **Codex gate ⏳ следующий шаг** → bounded execution surface ❌ →
bounded execution session ❌ → seal ❌. То есть направление и план доказаны и приняты,
два из трёх гейтов пройдены; впереди Codex-гейт, затем ограниченное исполнение и печать.

**Связь с памятью (почему это первый пилот Knowledge Substrate).** Entity Substrate был выбран
эталонной темой именно потому, что по нему есть и строгий in-repo канон (direction/plan/gates —
текущая авторитетная линия), и длинная история обсуждений во внешних чатах (эволюция идеи).
Это идеальный тест органа памяти: канон даёт CURRENT_AUTHORITY, чаты дают timeline и ветки идей,
а свежесть разводит «что актуально сейчас» и «что осталось историей».

**Дисциплина (инварианты, которые нельзя нарушать при постройке Substrate).**
использовать локальный ingest старого проекта (не дёргать его на каждом шаге), не возобновлять
старый маршрут, не запускать старый демон, идти строго по текущему lawful_next, всё видимо в
дашборде, proof на каждый шаг, обязательная память, ограниченная остановка, scientific + Hermes +
Codex гейты, без демона/фона/сети, без заявлений AGI/L3.

**Следующий законный шаг для самого Substrate (отдельно от этого органа памяти):**
`run_entity_substrate_codex_gate_v1` → построить bounded execution surface → прогнать сессию →
валидировать → review → `seal_entity_substrate_v1` → и только затем `build_anna_mvp_direction_v1`.
