## Основная линия (worked-out main line)
**Что такое ANNA (одной фразой).** ANNA — это первая живая цифровая *сущность*, рождённая
через способность SOCC «Entity Substrate»: ассистент-администратор, который заменяет живого
ресепшн-администратора клиники 24/7, неотличимо от человека. Не бот — личность с памятью,
характером и историей по каждому клиенту.

**Чем НЕ является.** Не чат-бот, не набор скриптов, не один Telegram-скрипт. ANNA = личность
поверх ядра SOCC; чат-канал (Telegram/MAX/SMS/звонки) — лишь поверхность, ядро одно.

**Архитектура (как продукт, не как игрушка).**
- *Личность ANNA* — одна на все вертикали (вежливая, чёткая, мягкая, умная, без лишних слов).
- *Вертикальный агент* — ANNA в стоматологии имеет по умолчанию скилы вертикали: триаж боли,
  ответ на запрос, ведение к записи, занесение в CRM, работа с возражениями.
- *Скилы как товар* — стоматология это первый скилл; дальше барбершоп, пластика, клиники.
  Базовый функционал + докупаемые возможности (звонки, кофе под ключ, само-маркетинг).
- *Ядро = SOCC* — отсюда неубиваемость: дисциплина proof/gate, fallback-лестница исполнителей
  (Claude Code → Codex → Hermes → socc_self), память и история по каждому клиенту.

**Продуктовая рамка (цель — деньги).** ANNA — продукт по подписке для 1000+ клиник:
быстрый онбординг (одна команда → пакеты/правила), оплата/подписка, кабинет владельца,
CRM-хук, регистрация активации в SOCC. Каждая активация регистрируется ядром.

**Линия рождения (порядок строг).** ANNA НЕ начинает строиться, пока не запечатан
Entity Substrate (математически доказанный, аги-инженерно выверенный субстрат рождения
сущностей). Сначала субстрат → потом ANNA как первая сущность на нём.

**Эволюция обсуждений (W0→W5).** Survival → Truth → Law → Surface/Live (Telegram live-ответ) →
Stabilization (gateway/RPC) → Memory attach. Источники: `ANNA последний этап*.md/.txt`,
`Развитие бота Анна.md`, persona-протоколы wavecore-bot, dental-triage (Obsidian).
