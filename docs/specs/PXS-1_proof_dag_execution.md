# PXS-1 — Proof-Gated DAG Execution Specification

> Статус: **DESIGN / не запечатан в канон.** Печать в sovereign canon — за оператором, по закону SOCC.
> Версия: 1.0 · Слой: штабная инженерия (как работа команды честно движется)
> Парный документ: [TFS-1 — Team Functor](./TFS-1_team_functor.md)

---

## 0. Зачем этот документ

TFS-1 ответил, **что рождается** — команда сущностей под любой продукт. PXS-1 отвечает на второй
страх дословно:

> «процесс 1 done → start процесс 2, и так автоматом, **без обмана**.»

Это не пожелание, а **доказуемое свойство механизма**. Обещание PXS-1:

> **Процесс 2 физически не может стартовать, пока процесс 1 не доказан реальностью.**
> Не «договорились не запускать раньше» — а *нет открытой двери*, пока нет proof.
> Соответственно: если ты видишь, что система перешла к шагу N, — значит все шаги до N
> закрыты честно. Иначе перехода бы не было.

PXS-1 **не выдумывает** новый движок. Он формализует уже построенный и многократно валидированный
`scripts/socc/socc_lawful_step_engine_v1.py` и расширяет его с **линейной цепочки** (`current → next`)
до **DAG из сущностей** (SCOUT → HERMES → … , LEDGER ← все). Карта соответствия «понятие PXS-1 →
реальный символ кода» — в §11. Ничего в этом документе не висит в воздухе.

## 1. Объекты

### 1.1 Атом (Atom) — `a`
Минимальный **провабельный** шаг работы. Меньше атома доказывать нечего.

```
a = ⟨ id, owner, action, pre, eff, Φ, key ⟩
```

| поле | смысл |
|---|---|
| `id` | уникальный id шага в DAG |
| `owner` | сущность-владелец `Eᵢ` (роль из TFS-1: кто отвечает) |
| `action` | операция из грамматики роли `action ∈ Σ_owner` |
| `pre` | множество входных рёбер (какие атомы должны быть PASS) |
| `eff` | эффект: какие артефакты/состояние пишет (детерминированно) |
| `Φ` | **предикаты-доказательства** — реальные проверки из файлового состояния (§1.3) |
| `key` | ключ идемпотентности: один и тот же `key` ⇒ один и тот же эффект (T4) |

> `Φ` — это те самые предикаты роли `Φᵢ`, что TFS-1 §1.1 передаёт сюда. Атом — место, где они проверяются.

### 1.2 Доказательство (Proof) — `π(a)`
Запись вердикта атома. **Единственный** носитель истины о том, закрыт атом или нет.
Структура (как пишет движок, дословно):

```
π(a) = {
  id, status ∈ {PASS, FAIL},
  checks: { name → bool },          # все реальные проверки и их результат
  hard_failures: [name],            # проверки, вернувшие не-True
  next_after_pass,                  # на PASS — id следующего узла; на FAIL — null
  next_lawful_step,                 # PASS → next ; FAIL → "manual_<id>_repair_required"
  truth_boundary,                   # что этот proof НЕ утверждает (граница честности)
  proof_hash                        # sha256(контент без хеша)[:16] — целостность
}
```

Закон формы: `status == PASS  ⟺  hard_failures == ∅`. Иного не бывает.

### 1.3 Проверка (Check) — реальная, не декларация-на-словах
Проверка **вычисляется из файлового состояния**, не объявляется истинной. Алфавит операторов
(точно как в движке, `_eval_check`):

| op | истина, когда |
|---|---|
| `exists` | файл существует |
| `proof_pass` | в файле `status == PASS` |
| `json_true` | значение по пути `== true` |
| `json_eq` | значение по пути `== value` |
| `json_nonempty` | значение по пути непусто |

Нет оператора «поверь мне». Любая проверка читает реальный файл. Это инженерный фундамент «без обмана».

### 1.4 Граф задач (Task-DAG) — `G = ⟨A, E⟩`
`A` — атомы, `E ⊆ A×A` — рёбра-зависимости. Ребро `u → v` значит «`v` нельзя начать, пока `u` не PASS».
`G` ацикличен по построению (зависимость от будущего запрещена — иначе старт недостижим).

### 1.5 Фронтир (Frontier) — `Fr(G)`
Множество атомов, **готовых к исполнению прямо сейчас**:

```
Fr(G) = { a ∈ A : a ещё не PASS  ∧  ∀(u→a) ∈ E : π(u).status == PASS ∧ ребро u→a открыто (§3) }
```

Фронтир — это «единственные открытые двери» из операционного контракта. CONDUCTOR всегда работает
только по фронтиру и никогда вне него.

### 1.6 Авторитет маршрута (Route authority)
Внешняя истина «на каком шаге система имеет право быть»: файлы
`CURRENT_ROUTE_AUTHORITY.json`, `AUTONOMY_PULSE_V1.json`, `CONTROL_PANEL_STATE_V1.json`.
Атом исполним, только если авторитет **согласованно** указывает на него (`authority_at_current`).
Это запрет на «прыжок через шаг» даже при наличии proof — топология и авторитет должны совпасть.

## 2. Ядро перехода — функция `step`

Один атом проходит через **одно** доказанное ядро (а не через 250 строк кастомного раннера на шаг).
Формально `step` — детерминированная, fail-closed функция:

```
step : (a, State) → (status, π(a), State')
```

Алгоритм (точно отражает `run_step`):

```
1. собрать checks:
     STANDARD_SAFETY (универсальный закон Λ₀, §5)
   ∪ authority_at_current            # авторитет указывает на a
   ∪ predecessor_proof PASS ∧ указывает на a    # входное ребро доказано
   ∪ ∀ upstream_proofs : PASS        # прочие входные рёбра DAG доказаны
   ∪ extra_checks (Φ атома)          # предметные предикаты, из файлов
2. hard ← { k : checks[k] ≠ True }
3. status ← PASS если hard = ∅ иначе FAIL
4. записать артефакт-вердикт + π(a) ВСЕГДА (и на PASS, и на FAIL — вердикт фиксируется)
5. if PASS:
     snapshot авторитета (backup) → atomic-commit перехода (§6) → синхронизировать зеркала
     если atomic-commit ≠ PASS:  hard += "ATOMIC_COMMIT_NOT_PASS"; status ← FAIL  # даже коммит проверяется
   if FAIL:
     маршрут НЕ двигается. next_lawful_step = "manual_<a>_repair_required". СТОП.
```

**Закон No-Fake-Pass.** PASS возможен ⟺ все проверки вернули `True`, и каждая вычислена из реального
файла. Нельзя «пометить» PASS — его можно только *заслужить состоянием*.

## 3. Ребро = доказательственный гейт (линейное → DAG)

Сердце расширения. В исходном движке маршрут линейный: один указатель `current_lawful_next`.
PXS-1 обобщает «1 done → 2 start» до произвольного DAG, **не меняя природу гейта**.

Ребро `u → v` **ОТКРЫТО** ⟺ одновременно:

```
(E1) π(u).status == PASS                          # источник реально доказан
(E2) π(u).next_after_pass == v   (предок указывает на v)   # доказательство адресовано именно v
(E3) ∀ прочих (w→v) ∈ E : π(w).status == PASS     # все входные рёбра v закрыты (upstream_proofs)
(E4) authority_at(v)                              # авторитет согласован на v
```

- **«1 done → 2 start»** — это частный случай: у `v` ровно одно входное ребро (`pre = {u}`),
  E3 пусто. Линейная цепочка `socc_lawful_step_engine` — это PXS-1 на пути-графе.
- **Передача «SCOUT done → HERMES start»** (TFS-1) = ребро `SCOUT.list → HERMES.touch`, открываемое
  только когда `π(SCOUT.list)=PASS` (есть список с доказанной болью) и адресовано HERMES.
- **Слияние** (LEDGER зависит от многих) выражается E3: атом LEDGER ждёт PASS всех входов.

Пока хоть одно условие ложно — ребро закрыто, `v ∉ Fr(G)`, атом `v` **не запускается**. Это и есть
«процесс 2 не может стартовать без обмана»: не дисциплина, а отсутствие открытой двери.

## 4. Исполнение по фронтиру — детерминированный цикл

```
loop:
  Fr ← Fr(G)                       # вычислить готовые атомы из реальных proof+авторитета
  если Fr = ∅:  останов (всё закрыто, либо упёрлись в FAIL — см. T2)
  для каждого a ∈ Fr (в топологическом порядке):
      step(a)
      если PASS:  открылись новые рёбра → Fr пересчитается на след. итерации
      если FAIL:  a остаётся в фронтире как закрытый; ребро из a не откроется → даунстрим заперт
```

Цикл детерминирован: при одном и том же состоянии файлов `Fr(G)` одинаков (T1, T3). Это **неподвижная
точка**: процесс движется ровно до границы доказанного и встаёт там, где proof кончился. Никакой атом
не исполняется «вперёд» от своей доказанной зоны.

> Это прямой ответ на «нужна УВЕРЕННОСТЬ, что нужные процессы будут исполняться». Уверенность здесь —
> не вера, а свойство: множество исполнимых атомов вычислимо, и оно ровно = доказанный фронтир.

## 5. Универсальный закон `Λ₀` — что проверяется ВСЕГДА

Каждый атом, независимо от роли, обязан пройти универсальный guard (`STANDARD_SAFETY` в коде).
Это инвариант, который нельзя обойти ни одним SPEC:

```
no_entity_birth · no_anna_birth · no_anna_instantiation · no_agent_spawn ·
no_daemon · no_background · no_network · no_scheduler ·
no_old_route_resume · no_mw_route ·
no_agi_claim · no_l3_claim · no_revenue_claim
```

Смысл: ни один шаг не имеет права тайно родить сущность, уйти в фон, в сеть, поднять демон или
**заявить недоказанное** (доход / AGI / уровень). Если шаг это делает — он FAIL по закону, маршрут стоит.
`Λ₀` — это базовый слой `Λ` из TFS-1; доменные `law_overrides` и `Λᵢ` роли **усиливают** его, не ослабляют.

> Граница честности (`truth_boundary`) пишется в каждый proof: что этот шаг доказал и, главное, чего он
> **не** утверждает. Фантом-OK невозможен по конструкции — недоказанное заявление = hard failure.

## 6. Атомарность перехода

Переход маршрута происходит **только** через enforced atomic-commit
(`socc_self_building_atomic_commit_enforcer_v1.py :: enforce_atomic_commit_transition`), не прямой записью.

- Перед коммитом — **snapshot** всех файлов авторитета в `lawful_step_backups/<step>_<ts>/` (откат возможен).
- Коммит сам возвращает вердикт; если он не PASS — атом **деградирует в FAIL** (`ATOMIC_COMMIT_NOT_PASS`).
- Следствие: **половинного перехода не бывает.** Либо авторитет целиком указывает на `v`, либо он не сдвинулся.
  Это исключает состояние «процесс 1 как бы done, а маршрут наполовину переехал».

## 7. Теоремы (фальсифицируемые гарантии)

Каждая проверяема тестом (§10); пока тест красный — гарантия не доказана, и мы это честно видим.

- **T1 — Soundness (No-Fake-Pass).** `π(a).status == PASS ⟹ ∀ c ∈ checks(a) : c = True`, и каждая `c`
  вычислена из реального файла. *Нет пути присвоить PASS в обход состояния.*

- **T2 — Fail-Closed.** `π(a).status == FAIL ⟹` авторитет не сдвинут `⟹` для любого `(a→v)`: E1 ложно
  `⟹ v ∉ Fr(G)`. **Процесс 2 не стартует.** Отказ не распространяется как «частичный успех» — он запирает.

- **T3 — No-Skip (топологическая честность).** Атом исполняется лишь при `authority_at(a)` ∧ всех входных
  рёбрах открытых `⟹` достичь узла `N` нельзя, не закрыв всю цепь предков `N`. *Виден шаг N → шаги до него честны.*

- **T4 — Resumability.** Рестарт после падения: движок перечитывает proof+авторитет, **заново вычисляет**
  `Fr(G)` и продолжает с фронтира. Уже-PASS атомы идемпотентны по `key` (тот же эффект, тот же `proof_hash`) —
  **двойного эффекта нет**. Процесс не теряется и не задваивается. (Это «вечная и неубиваемая» из TFS-1 §7.)

- **T5 — Auditability.** Каждый переход оставляет `π` + backup; `proof_hash` связывает содержимое.
  Любую историю «как дошли до N» можно восстановить по цепочке proof. Невидимых переходов нет.

- **T6 — Композиция с TFS-1.** Каждая сущность `Eᵢ` владеет под-DAG `Gᵢ`. Командный DAG —
  склейка под-DAG по рёбрам зависимостей ростера: `G_team = ⋃ Gᵢ ∪ deps`. Гейт §3 одинаков на внутренних
  и межсущностных рёбрах ⟹ передача между сущностями так же доказательственна, как шаг внутри одной.

## 8. Рабочая трасса — гейт SCOUT → HERMES

Конкретно, как «1 done → 2 start» выглядит на реальном переходе (маппинг на поля SPEC движка):

```
Атом u = SCOUT.build_list
  Φ(u): extra_checks = [
    { name: "list_exists",       file: ".../scout/targets.json",  op: exists },
    { name: "has_targets",       file: ".../scout/targets.json",  op: json_nonempty, path: "targets" },
    { name: "each_has_painproof",file: ".../scout/targets.json",  op: json_true,     path: "all_have_pain_evidence" },
  ]
  PASS ⟹ π(u){ status:PASS, next_after_pass:"HERMES.touch", proof_hash:… }

Атом v = HERMES.touch
  predecessor_proof: ".../scout/SCOUT_LIST_PROOF.json"   # E1∧E2: PASS и указывает на v
  upstream_proofs:  [ ".../scribe/POSITIONING_PROOF.json" ]   # E3: язык касания готов (SCRIBE)
  → v входит в Fr(G), ТОЛЬКО когда u PASS И позиционирование PASS И авторитет на v.
```

Пока у SCOUT нет списка с доказанной болью — `HERMES.touch` недостижим. HERMES не «забывает написать» и
не «пишет рано» — двери просто нет. Страх «а вдруг шаг проскочат» снят конструкцией, а не дисциплиной.

## 9. Эволюционный гейт (стыковка с TFS-1 §6)

Промоушн паттерна `Kᵢ → Gᵢ` (локальный опыт → глобальный геном роли) — это **тоже атом с proof-гейтом**,
не автоматический слив. Его предикат:

```
φ_promote(pattern) :=
    gain(fᵢ | pattern) ≥ θ   на ≥ k доменах        # прирост фитнеса воспроизводим (LEDGER, реально)
  ∧ anonymized(pattern) == True                     # обезличен (I2 приватность)
  ∧ ¬violates(Λ, pattern)                           # не нарушает закон
```

Только PASS этого гейта меняет `Gᵢ`. Эволюция, таким образом, — управляемый отбор по фитнесу через тот же
механизм доказательства: команда умнеет **монотонно и честно**, а не «дрейфует». Обгон конкурентов = сумма
доказанных приростов, каждый из которых прошёл гейт.

## 10. Тест приёмки (фальсифицируемый)

PXS-1 истинен ⟺ выполняются все:

```
(AT1 No-Fake-Pass) Подменяем входной файл атома на невалидный → step(a) = FAIL,
                   маршрут НЕ сдвинут, downstream-атом не вошёл в Fr(G).      [⇒ T1,T2]

(AT2 No-Skip)      Пытаемся исполнить атом v, минуя предка u (predecessor_proof не PASS)
                   → FAIL по authority/predecessor check, эффекта v нет.      [⇒ T3]

(AT3 Resumability) Убиваем процесс между PASS атома и записью зеркал; рестарт →
                   Fr(G) пересчитан, незавершённое доделано, уже-PASS не задвоен
                   (proof_hash идентичен).                                    [⇒ T4]

(AT4 Atomicity)    Заставляем atomic-commit вернуть не-PASS → атом деградирует в FAIL,
                   авторитет остаётся целиком на предыдущем узле.             [⇒ T6/§6]
```

Пока эти тесты не написаны/красные — гарантии заявлены, но не доказаны. Зелёные — «без обмана»
перестаёт быть словом и становится proof.

## 11. Карта соответствия: PXS-1 ⇄ реальный код

| понятие PXS-1 | реальный символ |
|---|---|
| `step(a)` ядро перехода | `socc_lawful_step_engine_v1.py :: run_step(spec)` |
| Check / операторы | `_eval_check` (`exists` · `proof_pass` · `json_true` · `json_eq` · `json_nonempty`) |
| `Λ₀` универсальный закон | `STANDARD_SAFETY` |
| `authority_at(a)` | `authority_at_current` (= `get_next` всех AUTHORITY_FILES = `current`) |
| E1∧E2 (входное ребро) | `predecessor_proof` + `proof_next(...) == current` |

| `Φ` атома | `extra_checks[]` |
| `π(a)` доказательство | объект `proof{…}` + `proof_hash = h16(...)` |
| атомарный коммит (§6) | `socc_self_building_atomic_commit_enforcer_v1.py :: enforce_atomic_commit_transition` |
| snapshot/откат | `lawful_step_backups/<current>_<ts>/` |
| зеркала состояния | `AUTONOMY_PULSE_V1.json` · `CONTROL_PANEL_STATE_V1.json` |
| FAIL-маршрут | `next_lawful_step = "manual_<current>_repair_required"` |

## 12. Что PXS-1 НЕ обещает (граница честности)

- Не обещает, что **содержание** атома правильно «по жизни» — обещает, что атом не пройдёт без своих
  предикатов. Качество предикатов `Φ` — отдельная инженерная ответственность владельца роли.
- Не обещает автономию там, где `Λ₀` её запрещает (сеть, фон, рассылка без approve). Автономия
  **зарабатывается** ослаблением конкретного guard под доказанной безопасностью, не включается оптом.
- Линейный движок сегодня доказан; **DAG-расширение (§3 E3, §4 фронтир) — DESIGN**, пока не пройдёт §10.
  Это и есть узел, который надо построить следующим, чтобы TFS-1 §8 (`A5` фабрика) стал зелёным.

> **Связка спеков.** TFS-1: *что рождается* (команда-функтор, дублируемая на любой продукт).
> PXS-1: *как её работа заперта реальностью* (proof-gated DAG, 1 done → 2 start без обмана).
> Вместе = фабрика команд, где каждое действие открывается только доказанным предыдущим.
