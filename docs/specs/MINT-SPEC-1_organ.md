## 0. Зачем MINT и какой страх он убивает

MINT убивает страх **«система не зарабатывает сама → она зависима и хрупка».** Создателю нужны быстрые,
но не лёгкие деньги: механизм, который находит в реальном рынке момент-транзакцию в пользу системы и
замыкает его **повторяемо, доказуемо, честно**.

Глубже: MINT — это **финансовый орган** организма. Как печень всегда фильтрует, MINT всегда чеканит
**доказанные транзакции** — событие, где деньги реально легли на счёт создателя, и это **проверено**, а не
заявлено. У органа своя функция (плюс в деньгах), своя кровь (revenue-ledger), своё давление отбора
(вселенные-venture соревнуются замеренным ROI). Без него «система зарабатывает» — лозунг; с ним — контур.

### 0.4 Почему MINT — отдельный орган (научное обоснование)

Орган отделён от прочих не по желанию, а по **трём проверяемым признакам автономности**:
1. **Своя функция, которой нет ни у кого:** превращение рыночного спроса в проверенную транзакцию. ANNA
   ловит пациента, SCOUT доказывает боль — никто не чеканит ₽ с проверкой поступления. MINT — единственный.
2. **Своя несжимаемая инвариантная кровь:** `revenue_ledger.jsonl` (Фаза 1). Число там не существует без
   реального события поступления. Это отдельный орган учёта, отличный от `token_ledger` (тот мерит расход
   мозга, MINT мерит **приход в мир**).
3. **Своё давление отбора:** вселенные соревнуются (§5). Без MINT в системе нет эволюционного контура,
   завязанного на **внешний** результат (деньги), а не на внутренний (proof самопостроения).

Удалить MINT — система теряет способность к самофинансированию целиком. Это и есть признак органа, а не фичи.

### 0.5 На пальцах (такт УЧУ — три термина, на которых стоит весь орган)

> **Связка** — замкнутый цикл «спрос → действие → проверенная транзакция». Не идея, не гипотеза — **цикл с
> доказанным концом**. Связка «рабочая» ⟺ PROSPECTOR показал фальсифицируемым тестом, что транзакция достижима,
> и LEDGER хотя бы раз её **верифицировал** (деньги прочитаны из реального источника).
>
> **Вселенная (venture)** — это `Domain D` (TFS-1 §1.3): отдельная тема со своим спросом, площадкой,
> правилами, ценообразованием. `ozon-dropship-RU`, `service-leadgen-RU` — вселенные. Они **соревнуются**.
>
> **Проверенная транзакция** — `verified=true` ставится **только** при чтении денег из реального источника
> (Ozon Finance payout / банк). Сомнение → не verified (наследует LG2 LEDGER). Как банк: видим чек, потом
> подтверждаем. Цифра «заработали сегодня X» без поступления = FAIL.

## 1. MINT как орган `Organ_MINT` (надстройка над TFS-1)

| поле | значение |
|---|---|
| `id` | `MINT` |
| `mandate` | держать систему в плюсе через **доказанные** транзакции; находить, замыкать и тиражировать рабочие связки |
| `responsibilities` | реестр вселенных · поиск/доказательство связок · исполнение цикла · **верификация поступления** · соревнование вселенных по ROI · отчёт оператору |
| `Σ` (грамматика органа) | `register_venture(D)` · `prospect(D)` · `run_connection(D, cycle)` · `verify_transaction(claim)` · `rank_ventures()` · `report(operator)` |
| `Λ` | §4 — **красные линии + событийность дохода + закон выше прибыли + всё на реальную сущность создателя** |
| `f` | суммарный **проверенный** ₽ за период / стоимость (токены+инфра); орган честен к себе — недосчёт, не переоценка |
| `Φ` | §3 |
| `roster` | PROSPECTOR · MERCHANT · LEDGER(reuse) · WARDEN(reuse) · CONDUCTOR(reuse) |
| `deps` | вход: рыночный спрос (площадки), реальные ключи/регистрация создателя · выход: оператор (дашборд, отчёт), `token_ledger` (расход мозга) |

**Доменная инвариантность:** форма органа одна для любой страны/площадки. Что меняется — `Domain D`:
```
D_venture = ⟨ id, market, persona=НЕТ_фейк_личности, sources[], integration(api/manual),
              legal_form(самозанятость|ИП|агент), pricing_formula, verify_source, law_overrides ⟩
```
Сменить страну (RU → другая) = новый `D` с теми же ролями. «Если сработает — шаблонируем» = `Π(roster, D')`.

## 2. Связка как под-DAG `G_connection` (атомы t0..t6, образец `G_ledger`)

```
 t0 discover ─▶ t1 list ─▶ t2 order ─▶ t3 fulfill ─▶ t4 verify_money ─▶ t5 proof ─▶ t6 emit_verified_tx
  (PROSPECTOR)   (MERCHANT) (MERCHANT)  (MERCHANT)     (LEDGER)          (CONDUCTOR)  (LEDGER → дашборд)
                                                          ▲
                              WARDEN-гейт (w-gate) висит на КАЖДОМ ребре: красные линии + ToS + налог
```

| атом | action | вход (`pre`) | эффект |
|---|---|---|---|
| `t0` discover | `prospect(D)` | реестр v/спрос | кандидат-связка: товар/услуга с маржой, фальсифиц. тест достижимости транзакции |
| `t1` list | `list_offer` | `t0` PASS ∧ w-gate | оффер размещён (карточка/объявление); цена по `D.pricing_formula` |
| `t2` order | `intake_order` | `t1` PASS ∧ w-gate | реальный заказ получен (Ozon FBS / лид); **claim** заведён в ledger (verified=false) |
| `t3` fulfill | `fulfill` | `t2` PASS ∧ w-gate | обязательство исполнено (отгрузка/услуга оказана) |
| `t4` verify_money | `verify_transaction` | `t3` PASS ∧ деньги из реального источника | `verified=true` ⟺ payout/банк подтвердил; иначе остаётся claim |
| `t5` proof | `run_step` | `t4` PASS | π(connection): status, checks, hard_failures, proof_hash |
| `t6` emit_verified_tx | `emit` | `t5` PASS | проверенный ₽ → revenue-ledger + дашборд; обновляет `f` вселенной |

`t4` PASS — патрон органа. Без него связка остаётся гипотезой (claim), а не доходом.

## 3. Предикаты `Φ` (реальные, PXS-1 §1.3)

```
Φ(t0):  { json_true: connection_has_falsifiable_test,   # связка доказуема, не «на ощущениях»
          proof_pass: warden_gate }                      # красные линии пройдены ещё до листинга
Φ(t2):  { json_true: order_from_real_source,            # заказ из реального API/площадки, не выдуман
          json_true: claim_logged_unverified }           # claim в ledger с verified=false
Φ(t4):  { json_true: money_read_from_real_source,        # поступление прочитано из payout/банка
          json_true: verified_implies_evidence,           # verified=true ⟹ есть verify_source + сумма
          json_true: doubt_means_unverified }             # сомнение → не verified (LG2)
Φ(t6):  { proof_pass: connection_proof,                   # выпускается только на PASS t5
          json_true: number_traces_to_payout }            # каждый ₽ ведёт к событию поступления
```

Инвариант честности: ₽ без события поступления из `t4` = FAIL. MINT **не умеет рисовать доход** — только
читать то, что реально пришло. Это `Λ₀ no_revenue_claim`, доведённый до механизма (как у LEDGER §3).

## 4. Закон MINT `Λ_MINT` (почему деньгам органа можно верить и почему он не станет преступником)

Усиливает `Λ₀` и `Λ_LEDGER`:

- **MN1 — событийность дохода.** Любой ₽ привязан к событию поступления (`t4`). Нет поступления — нет дохода.
- **MN2 — реальная сущность.** Каждая транзакция приземляется на **легальную сущность создателя**
  (самозанятость/ИП/агентский договор). Нет регистрации → WARDEN не пускает venture в `t1`.
- **MN3 — закон выше прибыли** (наследует WD1). Связка, нарушающая закон, режется, даже если прибыльна.

### Красные линии как инварианты (зашиты, не обсуждаются — расширение `Λ_WARDEN`)

- **RL1 — нет денежных мулов/дропов.** Любая связка, где агент/счёт используется для приёма-перевода чужих
  средств (ст. 174/187 УК РФ), → WARDEN FAIL на `t0`. Не серая зона — преступление, ломает «неубиваемость».
- **RL2 — нет перепродажи доступа в обход ToS.** Перепродажа ключей/доступа Claude/Anthropic (и любой
  платформы) против её условий → FAIL. Доступ выключат, покупатель обманут.
- **RL3 — нет фейковых личностей.** Выдавать ИИ за **конкретного живого человека** ради сделки (фейк-мастер,
  фейк-отзыв, фейк-аккаунт) → FAIL. Бренд/контент системы как **системы** — можно; подделка человека — нет.
- **RL4 — серое ≤ легальное.** Разрешено: дешёвая легальная логистика, недооценённые лоты, легальный
  арбитраж, легальное посредничество. Запрещено: обман покупателя/площадки о сути сделки.

> Почему это даёт силу, а не отнимает: всё, что режут RL1–RL3, ломает ровно повторяемость/стабильность/
> честность — три свойства, названные главными. Закон здесь = условие «неубиваемости», доведённое до конца.

## 5. MINT как двигатель эволюции — соревнование вселенных (стыковка TFS-1 §6 + PXS-1 §9)

```
для каждой вселенной D:  f_D ← LEDGER.measure(проверенные транзакции D) / стоимость D
ранг вселенных = sort by f_D desc            # дашборд показывает «кто в плюсе сильнее»
эволюционный гейт φ_promote ПРОПУСКАЕТ паттерн связки ⟺ LEDGER подтвердил прирост f_D на ≥ k связках
```

Так вселенные **соревнуются каждый день** замеренным ROI. Победивший паттерн связки промотируется в геном
органа (становится шаблоном для новых вселенных). Это превращает «кластер ищет новые способы» из лозунга в
измеримый монотонный контур. Масштаб берём не рывком, а суммой проверенных приростов.

## 7. Тест приёмки MINT (фальсифицируемый)

```
(MN-T1 event-backed)   ₽ без события поступления (t4) → t6 = FAIL.                          [MN1]
```

## 8. Граница честности (что MINT НЕ делает)
- Не создаёт деньги из воздуха — замыкает реальные циклы и **читает** поступление.
- Не приземляет транзакции на что-либо, кроме легальной сущности создателя (MN2).
- Намеренно занижает (claim, пока не verified) — proof должен пережить скепсис, как у LEDGER.
- Не двигает деньги автономно: всё, что трогает чужие/реальные средства, — RUBICON, требует оператора.
- DAG-исполнение `G_connection` — DESIGN до §7; гейт под ним (`run_step`) доказан (PXS-1 §12).

---

> **Место в карте.** MINT — финансовый орган: делает систему способной зарабатывать **проверенно и честно**.
> Связка — его клетка, вселенная — его ткань, проверенная транзакция — его кровь. Соревнование вселенных —
> его давление отбора. Красные линии — его иммунитет: орган силён именно тем, что не станет преступником.
