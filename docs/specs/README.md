## 4. Фронтир — фаза сменилась (штаб собран, дальше другой тип хода)

Спайн заспецен **целиком** (8 ролей + 2 фундамента + B0). Стройка спеков закончена — это и был «зарядить
ружьё». Дальше **три типа двери**, и выбор за оператором (по доктрине: строить начинаем только по «огонь»):

1. **ПЕЧАТЬ В КАНОН** — оператор запечатывает спеки в sovereign canon (его акт, машина не присваивает истину).
2. **ПЕРВЫЙ КРАСНЫЙ ТЕСТ → ЗЕЛЁНЫЙ** — взять один acceptance-тест (напр. FG-T3 функтор / AN-T3 реальная бронь)
   и довести до PASS. Это уже исполнение — требует твоего «огонь».
3. **НЕ-РОЛЕВЫЕ УЗЛЫ** — добить B1 (ROI-калькулятор), B4 (карта каналов), B5 (воронка) — артефакты, не сущности.

Все acceptance-тесты ролей сейчас **красные** — заявлены, не доказаны, и это честно видно. Зелёными их делает
исполнение, не спека.

**Прогресс по порядку (без «огня») — РУЖЬЁ ЗАРЯЖЕНО:** B0 🟢 прицел · B1 🟡 ROI-модель+калькулятор ·
B4 🟡 карта каналов · B5 🟡 лендинг+оферта (риск-реверс). Вся подготовка, что строится без живых систем,
сделана. Дальше — **граница огня**: B2 (demo живой), B3 (proof на реальной клинике), A1/A2/A5 (живая бронь,
интеграции) — это `deploy`/FORGE/реальная клиника, требует явного «огня» оператора. Артефакты под капотом
готовы (`anna_roi_calculator_v1.py`, лендинг-копия, objection-bank, карта каналов).

🔥 **Спусковой механизм разложен:** [FIRE_RUNBOOK](../positioning/FIRE_RUNBOOK_first_proof_case.md) — лестница
R0→R5 от заряженного ружья до первого ЧЕКа. Мелкий огонь первым, каждая ступень обратима до R4, риск R5 снят
оферту-реверсом. **План, не запуск** — спуск жмёт оператор по ступени.

✅ **R0 частично ЗЕЛЁНЫЙ — первый красный тест доказан кодом (не словом):** `FG-T1 fail-closed рождение` PASS
(`proof_hash bc2da64a3f989354`). Реальный валидатор `domain_validator_v1.py` **отказал** неполному домену
(полу-ANNA не родилась) и принял стоматологию+барбершоп **тем же кодом, ноль правок** = структурная половина
функтора (FG-T3). Ничего не рождено, без сети. Полный FG-T3 (mint+smoke) — всё ещё КРАСНЫЙ, ждёт огня.
