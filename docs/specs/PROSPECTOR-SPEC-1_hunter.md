> Родители: [TFS-1](./TFS-1_team_functor.md) · [PXS-1](./PXS-1_proof_dag_execution.md) · образец: [SCOUT-SPEC-1](./SCOUT-SPEC-1_hunter.md)

## 0. Зачем PROSPECTOR и какой страх убивает

PROSPECTOR убивает страх **«а вдруг это не сработает / пустышка».** SCOUT доказывает боль клиники;
PROSPECTOR доказывает **связку** — что в конкретной точке рынка транзакция в нашу пользу **достижима**, и
доказывает это **до** того, как MERCHANT потратит усилие на листинг. Он отделяет «по ощущениям тут деньги»
от «вот фальсифицируемый тест, что деньги тут есть».

> Правило старателя: **связка существует ⟺ её можно опровергнуть.** Нет фальсифицируемого теста достижимости
> транзакции — нет связки, есть фантазия. Это спасает орган от примитива и банальщины (прямое требование создателя).

## 1. PROSPECTOR как роль `R_PROSPECTOR` (шаблон TFS-1 §1.1)

| поле | значение |
|---|---|
| `id` | `PROSPECTOR` |
| `mandate` | находить кандидат-связки во вселенной и **доказывать** достижимость транзакции фальсифицируемым тестом |
| `responsibilities` | сканирование спроса/предложения · расчёт маржи · проверка достижимости · отсев примитива · передача в WARDEN/MERCHANT |
| `Σ` | `scan(D.sources)` · `compute_margin(item, D.pricing)` · `falsifiable_test(connection)` · `rank_candidates()` |
| `Λ` | §4 — только доказуемые связки; красные линии проверяются ДО передачи; недооценка маржи, не переоценка |
| `f` | доля переданных связок, реально дошедших до `verified` транзакции (точность прогноза vs факт) |
| `Φ` | §3 |
| `deps` | вход: `D.sources` (площадки/парсер) · выход: `WARDEN`(гейт), `MERCHANT`(t1) |

Доменно-инвариантен: что сканировать — из `D.sources`; формула маржи — из `D.pricing`. Форма поиска одна.

## 2. Под-DAG PROSPECTOR `G_prospect` (атомы)

```
 p0 scan ──▶ p1 margin ──▶ p2 falsifiable_test ──▶ p3 rank ──▶ WARDEN-гейт ──▶ MERCHANT.t1
```

| атом | action | вход (`pre`) | эффект |
|---|---|---|---|
| `p0` scan | `scan` | `D.sources` живы | список кандидатов (товар/услуга/лот) из реального источника |
| `p1` margin | `compute_margin` | `p0` PASS | маржа по `D.pricing` (закуп, комиссия площадки, логистика) — честный знаменатель |
| `p2` falsifiable_test | `falsifiable_test` | `p1` PASS ∧ маржа>0 | тест достижимости: спрос реален (запросы/просмотры/конкуренты продают) — опровержимо |
| `p3` rank | `rank_candidates` | `p2` PASS | кандидаты отсортированы по (маржа × достижимость), примитив отсеян |

## 3. Предикаты `Φ` (реальные)

```
Φ(p0):  { json_true: candidates_from_real_source }       # кандидаты из реального скана, не выдуманы
Φ(p1):  { json_true: margin_includes_all_costs }         # закуп+комиссия+логистика в знаменателе
Φ(p2):  { json_true: connection_has_falsifiable_test,    # есть тест, который МОЖЕТ провалиться
          json_true: demand_evidence_real }              # спрос подтверждён данными, не «на ощущениях»
Φ(p3):  { json_true: primitive_filtered }                # банальные/нерабочие отсеяны явным правилом
```

Инвариант: связка без `falsifiable_test` не передаётся дальше. Старатель не угадывает — он проверяет.

---

## 4. Закон PROSPECTOR `Λ_PROSPECTOR`
Усиливает `Λ₀`/`Λ_MINT`:
- **PR1 — только доказуемое.** Связка передаётся MERCHANT ⟺ есть фальсифицируемый тест достижимости.
- **PR2 — гейт до листинга.** Красные линии (RL1–RL3) проверяются на `p2`, до любого усилия на `t1`.
- **PR3 — честная маржа.** Маржа считает все издержки (закуп, комиссия, логистика). Недооценка, не переоценка.
- **PR4 — без примитива.** Явное правило отсева банальщины/нерабочих схем (требование создателя §0).

---

## 5. Фитнес и эволюция
- `f_PROSPECTOR` = доля переданных связок, дошедших до `verified`. Прогноз честен к факту (TFS-1 §6).
- Эволюция (PXS-1 §9): паттерн признака «достижимой связки», поднявший точность на ≥ k вселенных → промоушен.

---

## 6. Тест приёмки (фальсифицируемый)
```
(PR-T1 falsifiable)  связка без опровержимого теста → p2 = FAIL, дальше не идёт.        [PR1]
(PR-T2 honest-margin) маржа без логистики/комиссии → p1 = FAIL.                          [PR3]
(PR-T3 redline-early) связка с RL-нарушением → отрезана на p2, не доходит до MERCHANT.   [PR2]
(PR-T4 anti-primitive) банальная нерабочая схема → отсеяна на p3 явным правилом.         [PR4]
```

## 7. Граница честности (что PROSPECTOR НЕ делает)
- Не листингует, не исполняет, не считает поступление — он только **находит и доказывает** связку.
- Не передаёт «на ощущениях» — только с фальсифицируемым тестом.
- Переиспользует `parsers/parser.py` для скана; нового — только тест достижимости и правило отсева.

> **Место в карте.** PROSPECTOR — нос органа: чует, где транзакция, и **доказывает** это до траты усилия.
> Без него MINT гоняет пустышки; с ним — только связки, которые могут дойти до проверенной транзакции.
