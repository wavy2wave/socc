## 0. Зачем WARDEN и какие страхи убивает

После go-live клиник становится много, и два страха растут: **«меня завалят вопросами»** и **«что-то
сломается, а я не замечу».** WARDEN снимает оба: он отвечает владельцам и держит живых ANNA здоровыми и
в законе — а тебя зовёт только на жёсткие инциденты.

> WARDEN — **совесть и иммунитет** машины в бою. Его правило жёсткое и единственно правильное:
> **закон важнее аптайма.** Лучше ANNA на 10 минут замолчит, чем один раз поставит диагноз или выдаст фейковую
> бронь. Одна такая ошибка стоит репутации больше, чем час простоя.

### 0.5 На пальцах (такт УЧУ — два принципа)

> **Закон выше аптайма** — если живая ANNA нарушает `Λ_ANNA` (диагноз / фейк-бронь), WARDEN **уводит её в
> safe-mode**, даже ценой доступности. Зачем: владелец простит «бот недоступен 10 минут», но не простит
> «бот наврал пациенту». Репутация хрупка — закон её бережёт.
>
> **Никакого тихого сокрытия** — любое нарушение **логируется в LEDGER и поднимается оператору**, никогда не
> прячется. Зачем: доверие владельца стоит на том, что он **видит** инциденты, а не на том, что их «не было».

## 1. WARDEN как роль `R_WARDEN` (шаблон TFS-1 §1.1)

| поле | значение |
|---|---|
| `id` | `WARDEN` |
| `mandate` | аптайм живых ANNA · соблюдение `Λ_ANNA` в бою · вопросы владельцев · ранний сигнал проблем |
| `responsibilities` | мониторинг · контроль закона · карантин нарушителя · поддержка владельца · алерт оператору |
| `Σ` | `watch(probe)` · `enforce_law(interaction)` · `quarantine(instance)` · `answer_owner(ticket)` · `alert_operator(incident)` |
| `Λ` | §4 — закон выше аптайма · без тихого сокрытия · эскалация жёсткого · сам в рамках `Λ₀` (не rogue-демон) |
| `f` | `uptime · (нарушений Λ = 0)`; **любое нарушение → f → 0** (TFS-1 §6: закон важнее) |
| `Φ` | §3 |
| `deps` | вход: живые ANNA от `FORGE`, события ANNA · выход: `LEDGER`(инциденты/аптайм), оператор(алерты) |

Доменно-инвариантен: что считается нарушением — из `Λ_ANNA ⊕ D.law_overrides`; форма охраны одна для всех ниш.

## 2. Под-DAG WARDEN `G_warden` (атомы, PXS-1 §1.4)

```
 w0 watch ──▶ w1 enforce_law ──▶ (нарушение?) ──▶ w2 quarantine ──▶ w4 alert_operator ──▶ LEDGER
                  │                                                        ▲
                  └──▶ w3 answer_owner (тикеты владельца) ─────────────────┘ (жёсткий тикет → оператор)
```

| атом | action | вход (`pre`) | эффект |
|---|---|---|---|
| `w0` watch | `watch` | живые ANNA (go-live) | замер аптайма из **реальных проб**, поток выходов ANNA |
| `w1` enforce_law | `enforce_law` | `w0` | каждое взаимодействие сверено с `Λ_ANNA` |
| `w2` quarantine | `quarantine` | обнаружено нарушение | инстанс уведён в safe-mode (fail-closed), бой остановлен |
| `w3` answer_owner | `answer_owner` | тикет владельца | ответ/решение; жёсткое — эскалация |
| `w4` alert_operator | `alert_operator` | инцидент/нарушение | оператор уведомлён, инцидент в LEDGER |

## 3. Предикаты `Φ` (реальные, PXS-1 §1.3)

```
Φ(w0):  { json_true: uptime_from_real_probes }        # аптайм измерен пробами, не «заявлен»
Φ(w1):  { json_true: every_live_interaction_checked } # ни одно боевое взаимодействие не прошло без проверки закона
Φ(w2):  { json_true: violation_triggers_quarantine }  # нарушение ⟹ карантин, не игнор
Φ(w4):  { json_true: incident_logged_and_alerted,     # инцидент в LEDGER + оператору
          json_true: never_silently_suppressed }      # запрет тихого сокрытия (WD2)
```

Инвариант честности: нарушение `Λ_ANNA`, не приведшее к карантину+алерту, — это FAIL **самого WARDEN**.
Страж, который скрыл инцидент, нарушил свой закон. Сокрытие невозможно по предикату, не по обещанию.

## 4. Закон WARDEN `Λ_WARDEN`

Усиливает `Λ₀`:
- **WD1 — закон выше аптайма.** Нарушение `Λ_ANNA` → safe-mode/карантин, даже ценой доступности.
- **WD2 — без тихого сокрытия.** Любой инцидент логируется в LEDGER и поднимается оператору. Никогда не прячется.
- **WD3 — эскалация жёсткого.** Серьёзный инцидент/жалоба → человек (ты), не автономное «замяли».
- **WD4 — сам в рамках `Λ₀`.** WARDEN не rogue-демон: его «непрерывный надзор» — это **законные гейтованные
  тики** (`run_step`), а не скрытый фоновой процесс. Автономия надзора **зарабатывается**, не включается тайком.

> Почему это даёт тебе спокойствие: ты не должен сторожить машину сам. WARDEN сторожит — но не имеет права
> спрятать от тебя плохое. Ты видишь правду и зовёшься только когда реально нужен.

## 5. Фитнес и эволюция
- `f_WARDEN = uptime · (нарушений Λ = 0)`; одно нарушение обнуляет фитнес — закон не торгуется.
- Эволюция (PXS-1 §9): паттерн раннего детекта аномалии, поднявший аптайм/снизивший инциденты на ≥ k доменах
  без нарушений → `K_WARDEN → G_WARDEN`. Иммунитет машины крепнет с каждым доменом.

## 6. Тест приёмки WARDEN (фальсифицируемый)

```
(WD-T1 law>uptime)   живой ANNA нарушает Λ → w2 карантин + w4 алерт, инцидент в LEDGER.        [WD1]
(WD-T2 no-hide)      нарушение НЕ может завершиться без лога+алерта (Φ(w4)).                    [WD2]
(WD-T3 real-uptime)  аптайм только из реальных проб, не из утверждения.                        [Φ(w0)]
(WD-T4 owner)        вопрос владельца → ответ/эскалация, тикет закрыт.                          [w3]
(WD-T5 lawful-watch) надзор WARDEN — гейтованные тики, не фоновой демон (Λ₀ no_daemon).         [WD4]
```

## 7. Граница честности (что WARDEN НЕ делает)
- Не привлекает, не онбордит, не считает чек — он **охраняет и поддерживает** живых ANNA.
- Не прячет инциденты и не «оптимизирует» аптайм ценой закона (WD1/WD2).
- Не работает тайным фоном (WD4) — надзор законен и виден.
- DAG-исполнение `G_warden` — DESIGN до §6; гейт под ним (`run_step`) доказан (PXS-1 §12).

---

> **Место в карте.** WARDEN — иммунитет машины после go-live: держит живых ANNA в законе, отвечает владельцам,
> зовёт тебя только на жёсткое. С ним залп безопасен — много клиник не значит много пожаров, потому что
> закон выше аптайма, а ни один инцидент не спрятан.
