## 0. Зачем SCRIBE и почему он на фронтире

SCRIBE кует **боеприпасы**: позиционирование, ROI-модель, objection-bank, demo-промпты, лендинг, proof-кейс.
Он на фронтире, потому что его первый артефакт — **B0 (позиционирование)** — это `upstream` сразу для двух
вещей: атома `HERMES.draft` (h1) и языка demo-ANNA. Без B0 HERMES заспецен, но писать касания не может.

> SCRIBE убивает страх «я не умею в маркетинг». Тексты, цифры, ответы на возражения — кует сущность из
> твоей же доктрины и реальных чисел LEDGER. Ты не сочиняешь — ты подтверждаешь.

### 0.5 На пальцах (такт УЧУ — три термина для B0)

> **Категория** — в какую полку кладёт тебя владелец в голове. Не «ИИ-бот», а *«администратор, который не
> спит»*. Кто владеет категорией — тому не нужно сравнение по фичам.
>
> **Враг** — не конкурент, а **проблема-злодей**, против которой ты герой. Тут враг = *тишина после 18:00 /
> пропущенный звонок*. Враг даёт касанию эмоцию: владелец ненавидит терять пациентов, не «робота».
>
> **Моат (ров)** — почему тебя не скопируют за неделю. Тут моат = *память (помнит каждого пациента) +
> proof-леджер (не врёт, не диагностирует) + сетевой эффект*. Моат вплетается в обещание, а не висит сбоку.

## 1. SCRIBE как роль `R_SCRIBE` (шаблон TFS-1 §1.1)

| поле | значение |
|---|---|
| `id` | `SCRIBE` |
| `mandate` | ковать боеприпасы воронки из доктрины оператора и реальных чисел LEDGER |
| `responsibilities` | позиционирование · ROI-модель/калькулятор · objection-bank · demo-промпты · лендинг · сборка proof-кейса |
| `Σ` | `forge_positioning(D)` · `build_roi(D, ledger)` · `draft_objections(D)` · `author_demo_prompts(D)` · `write_landing(D)` · `assemble_proof_case(ledger)` |
| `Λ` | §4 — **любое числовое/ценностное заявление обязано трассироваться к реальному числу LEDGER**; без выдуманного ROI (Λ₀ `no_revenue_claim`) |
| `f` | прирост `reply-rate` касаний HERMES на языке SCRIBE · demo→book rate (LEDGER) |
| `Φ` | §3 |
| `deps` | вход: `LEDGER`(числа), доктрина оператора · выход: `HERMES`(позиционирование, objection-bank), `ANNA`(demo-промпты), `B5`(лендинг/оферта) |

Доменно-инвариантен: для барбершопа SCRIBE кует те же типы артефактов, меняется `D` (вокабуляр, тикет, враг ниши).

## 2. Под-DAG SCRIBE `G_scribe` (атомы, PXS-1 §1.4)

```
 c0 positioning (B0) ──▶ c1 roi-model ──▶ c2 objection-bank ──▶ c3 demo-prompts ──▶ c4 landing ──▶ c5 proof-case
        │                                        │                      │
        └──────────────▶ HERMES.draft (h1)       └──▶ HERMES.answer (h5) └──▶ ANNA(demo)
```

| атом | action | вход (`pre`) | эффект | открывает |
|---|---|---|---|---|
| `c0` positioning | `forge_positioning` | доктрина оператора | категория·враг·обещание·моат (1 стр.) | `HERMES.h1`, `ANNA demo` |
| `c1` roi-model | `build_roi` | `c0` PASS ∧ числа LEDGER | формула потеря→возврат + калькулятор | `B1` |
| `c2` objection-bank | `draft_objections` | `c0` PASS | честные ответы на типовые возражения | `HERMES.h5` |
| `c3` demo-prompts | `author_demo_prompts` | `c0` PASS | язык/тон demo-ANNA по позиционированию | `B2` |
| `c4` landing | `write_landing` | `c0`+`c1` PASS | лендинг с оффертой | `B5` |
| `c5` proof-case | `assemble_proof_case` | `c1` PASS ∧ proof клиники из LEDGER | ЧЕК-кейс: ₽X возвращено, видео | `B3` |

`c0` = узел **B0** дерева кампании. Его PASS — первая разблокировка всей правой ветки (ПУШКА).

## 3. Предикаты `Φ` (реальные, PXS-1 §1.3)

```
Φ(c0):  { json_true: has_category ∧ has_enemy ∧ has_promise ∧ has_moat,   # все 4 элемента на месте
          json_true: one_page,                                            # ≤ 1 страница (дисциплина прицела)
          json_true: operator_understood }                               # proof B0 = «ты понял», не «написано»
Φ(c1):  { json_true: every_number_traces_to_ledger }                     # нет числа без источника
Φ(c2):  { json_nonempty: objections[], json_true: no_unproven_claims }
Φ(c5):  { proof_pass: clinic_proof_from_ledger }                         # proof-кейс только на реальном чеке
```

Инвариант честности: `c1`/`c5` с числом, не привязанным к LEDGER, = FAIL. SCRIBE **не рисует ROI из
воздуха** — каждая цифра трассируется к реальному замеру. Это прямой `Λ₀ no_revenue_claim`.

---

## 4. Закон SCRIBE `Λ_SCRIBE`

Усиливает `Λ₀`:
- **W1 — трассируемость чисел.** Любой ROI/«N заявок»/«₽X» обязан ссылаться на запись LEDGER. Нет ссылки = FAIL.
- **W2 — без обещаний продукта, которого нет.** Текст не обещает фич, которые ANNA не держит (синхронизация с `Φ` ANNA).
- **W3 — proof-кейс только на реальном чеке.** `c5` берёт число у LEDGER, не у воображения.

> Почему это снимает страх, а не добавляет: позиционирование, прошедшее `Φ(c0)`, — проверено на «ты понял».
> Ты выходишь из B0 не с текстом, а с пониманием — отсюда исчезает «я не разбираюсь».

## 5. Рождение, фитнес, эволюция

- `Π(R_SCRIBE, D)` (TFS-1 §2): mount доктрину + числа LEDGER, attach `Λ_SCRIBE`, register
  `entity_substrate/entities/<D>/scribe/` + proof.
- `f_SCRIBE` = прирост `reply-rate`/`book-rate` от артефактов (меряет LEDGER через HERMES/ANNA).
- Эволюция (PXS-1 §9): формулировка/крючок, поднявшая конверсию ≥ θ на ≥ k доменах → `K_SCRIBE → G_SCRIBE`.
  Лучшее позиционирование становится общим геномом: стоматология учит барбершоп структуре прицела.

## 6. Тест приёмки SCRIBE (фальсифицируемый)

```
(WR1 four-elements) B0 без одного из {категория,враг,обещание,моат} → c0 = FAIL.        [Φ(c0)]
(WR2 ledger-traced) ROI с числом без ссылки на LEDGER → c1 = FAIL.                       [W1]
(WR3 unblock)       c0 PASS ⟹ HERMES.h1 и ANNA-demo получают язык (upstream открыт).    [PXS-1 §8]
(WR4 proof-real)    proof-кейс без реального чека LEDGER → c5 = FAIL.                     [W3]
```

## 7. Граница честности
- SCRIBE кует слова и формулы — не рассылает (HERMES), не считает факт (LEDGER), не онбордит (FORGE).
- Не утверждает доход/ROI без числа LEDGER (W1, `Λ₀`).
- DAG-исполнение `G_scribe` — DESIGN до §6; гейт под ним (`run_step`) доказан (PXS-1 §12).
