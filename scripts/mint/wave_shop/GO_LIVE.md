## ⚠️ ОДНА ВАЖНАЯ ПРАВКА К ПЛАНУ (честно, до того как жать)

Ты выбрал «цифровые товары, риск НЕТ». Но по факту **все 9 товаров в каталоге — `kind=gateway`**: каждый продаёт **доступ к ИИ через обойму**, а не простой цифровой файл. Простого цифрового товара (ключ-со-склада / вечный текст) в каталоге сейчас **нет ни одного**.

Из этого следуют два честных факта:

1. **Товар «живой» ровно настолько, насколько жива обойма.** Если 2 ключа не достают до провайдера — клиент заплатит и получит ошибку. Это и есть единственный реальный риск здесь (не деньги вперёд — а продать неработающий доступ).
2. **`WAVE_UPSTREAM_URL` в `.env` не задан** → шлюз по умолчанию идёт на `https://openrouter.ai/api/v1`. По нашей же памяти [[ru-egress-image-api-block]] egress этой машины = RU, и openrouter/openai/gemini режут RU **до ключа**. Значит с этой машины ключи, скорее всего, **мертвы на входе** — но с другого egress (твой сервер/VPS/прокси) могут быть живы. Это ты знаешь, а я нет.

Поэтому «первый ₽ за часы» — да, **если** обойма достаёт провайдера оттуда, где реально крутится бот. Это шаг 1.

## ШАГ 1 (только ты, КРИТИЧНО): апстрим под формат ключей — иначе сожжёшь обойму

Оба заряженных ключа — формат **`sk-*`, НЕ `sk-or-v1-*`**. Дефолтный `WAVE_UPSTREAM_URL` = openrouter, а он ждёт `sk-or-v1-…`. Если запустить как есть — **первый же клиентский запрос вернёт 401, и патрон умрёт НАВСЕГДА** (dead-persist по отпечатку в `data/upstream_pool_state.json`, переживает рестарт). Ровно поэтому ты сам обнулил файл утром 2026-08-18.

> Загрузка ключей в файл патрон НЕ жжёт (проверено: `stats → total=2 alive=2 dead=0`, 0 сетевых вызовов). Жжёт **только живой запрос через поднятый шлюз** с неверным апстримом. Поэтому весь риск — здесь, и он снимается одной строкой.

Задай URL провайдера, которому эти `sk-*` ключи РОДНЫЕ, и проверь живьём оттуда, где будет крутиться бот:

```bash
cd SOCC/scripts/mint/wave_shop

# провайдер этих ключей (НЕ openrouter — openrouter их не примет):
echo 'WAVE_UPSTREAM_URL=https://api.<провайдер-этих-ключей>.com/v1' >> .env

# 1. поднять только шлюз
python3 -m gateway.proxy &

# 2. выдать себе тестовый клиентский токен (оффлайн, денег не тратит)
python3 -m gateway.issue --plan demo --user <твой_tg_id>   # → wave-...

# 3. ЖИВОЙ вызов — вот это и есть проверка обоймы (жжёт патрон при неверном URL!):
curl -s http://127.0.0.1:8790/v1/models -H "Authorization: Bearer wave-..." | head
```

- **Пришёл список моделей** → обойма живая на этом URL → шаг 2.
- **401** → URL/формат не совпал. НЕ повторяй вслепую (каждый 401 = −1 патрон навсегда). Останови шлюз, поправь `WAVE_UPSTREAM_URL`, при нужде верни ключ из бэкапа. Витрину не открывай.

> `GET /health` уже сейчас скажет `upstream_configured: true` — но это лишь «в обойме есть не-мёртвые ключи», НЕ «они достают провайдера». Единственный оракул живости — вызов выше.

## АВТОСПИСАНИЕ (автопродление подписок + автопополнение кошельков) — ЗАРЯЖЕНО НА ПРЕДОХРАНИТЕЛЕ

> Это отдельный слой поверх разовых продаж: подписка сама продлевается, а потокенный кошелёк сам пополняется с **привязанной карты**, когда трафик кончился. Самая выгодная модель — деньги идут без нового касания клиента. Движок — `renewals.py`, ставится на `launchd` раз в час.

**Состояние сейчас — заряжено, но курок на предохранителе.** Готовый агент лежит в `ops/com.socc.waveshop.renewals.v1.plist` и **специально НЕ установлен**. Даже когда установишь — он приходит с флагом `--dry-run`: раз в час считает, *сколько бы* продлил и пополнил, пишет в лог и **не двигает ни копейки, ни байта**. Доказано `tests/renewals_dry_v1.py` (**14/14**) на реальной очереди работ (просроченная подписка + просевший кошелёк) — сверка данных побайтово.

**Два физических рубежа RUBICON (тот же тест):**
1. `--dry-run` = только отчёт. Ноль списаний, ноль сообщений, ноль записей.
2. Даже сняв `--dry-run`, **без ключей ЮKassa движок не двинет денег**: `provider.configured=False` → ранний выход перед любым `charge`, касса не дёргается ни разу.

**Предпосылки, без которых вооружать НЕЧЕМ (все — твои):**
- ключи ЮKassa в `.env` (`WAVE_YOOKASSA_SHOP_ID` + `WAVE_YOOKASSA_SECRET_KEY`) — карта клиента привязывается только через реальный платёж ЮKassa с `save_payment_method`;
- открыт хотя бы один тариф-подписка или потокенный (иначе продлевать/пополнять нечего);
- шаг 1 (живой апстрим) уже зелёный — иначе продлишь доступ, который не работает.

**Установить (сухо, безопасно — можно прямо сейчас):**
```bash
cp SOCC/scripts/mint/wave_shop/ops/com.socc.waveshop.renewals.v1.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.socc.waveshop.renewals.v1.plist
# разовая проверка вручную (напечатает отчёт в лог, ничего не спишет):
launchctl kickstart -k gui/$(id -u)/com.socc.waveshop.renewals.v1
cat SOCC/MEMORY_WAVE/reports/mint/wave_shop/renewals.launchd.out   # «СПИСАНИЙ НЕ ДЕЛАЕМ …»
```

**ВООРУЖИТЬ боевое автосписание (только ты, когда предпосылки готовы):**
```bash
# 1) убрать строку   <string>--dry-run</string>   из установленного plist
# 2) перезагрузить агент:
launchctl unload ~/Library/LaunchAgents/com.socc.waveshop.renewals.v1.plist
launchctl load   ~/Library/LaunchAgents/com.socc.waveshop.renewals.v1.plist
```
**Снять с боевого** — вернуть строку `--dry-run` (или `launchctl unload`). Курок всегда возвращается на предохранитель одним словом.

> Частота — раз в час на :23. Для потокенных кошельков час — приемлемая задержка на MVP; хочешь живее (напр. каждые 15–30 мин на тяжёлых клиентов) — поправь `StartCalendarInterval` в plist перед `load`.

## Закон этой операции (не нарушать)

- **RUBICON цел:** магазин только принимает деньги (касса Stars на токене бота). Наружу сам ничего не покупает, обойму не пополняет автоматом.
- **Деньги вперёд не тратим:** ни одной закупки до оплаты клиента. Товар=доступ, склад=твои ключи.
- **Не продавать воздух:** витрину открываем ТОЛЬКО после зелёного шага 1. Это единственный реальный риск в этой линии.
- **Файлы не тронуты:** этот go-live ничего не переписал в боевом каталоге — он и сейчас в состоянии «сейф закрыт» (0 активных). Открываешь ты, шагом 2.
