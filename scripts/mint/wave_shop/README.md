# WAVE SHOP — Telegram-магазин цифровых товаров

Витрина + касса (Stars/ЮKassa/крипта) + мгновенная выдача + честные рефералы.  
**Stdlib-only:** ноль внешних зависимостей, запуск на голом `python3`.

---

## Быстрый старт

### 1. Получите токен бота
```bash
# У @BotFather в Telegram:
# /newbot → имя → получаете токен вида 123456:ABC-DEF...
```

### 2. Настройте .env
```bash
cp .env.example .env
# Откройте .env и вставьте:
# WAVE_BOT_TOKEN=ваш_токен_от_BotFather
# WAVE_ADMIN_IDS=ваш_telegram_user_id
```

Узнать свой `user_id`: напишите [@userinfobot](https://t.me/userinfobot) в Telegram.

### 3. Загрузите товары и склад
Откройте `data/catalog.json` — там 3 демо-товара. Замените на реальные:
```json
{
  "id": "my_product_1",
  "title": "Мой товар",
  "description": "Описание",
  "price_rub": 500,
  "stars_price": 30,
  "kind": "key",
  "active": true
}
```

**Типы товаров (`kind`):**
- `"key"` — цифровой ключ/код. Выдаётся со склада (`data/stock.json`).  
  Пополнить склад: `/stock my_product_1 KEY-AAA,KEY-BBB,KEY-CCC` (в боте, от админа).
- `"lifetime"` — вечный доступ. Выдаётся текст из `lifetime_payload`, склад не нужен.

### 4. Запустите — одной командой
```bash
./run.sh
```
`run.sh` — запуск «под ключ»: проверяет `.env`, поднимает бота с
**авто-перезапуском** (упал — поднимется через 3с), и если в `.env` задан
`WAVE_UPSTREAM_KEY` — заодно поднимает шлюз. Остановить — `Ctrl+C`.

Или напрямую, без обёртки:
```bash
python3 bot.py
```

Увидите:
```
🌊 WAVE SHOP запущен: @your_bot_username
   Кассы: stars
   Админы: [123456789]
   Товаров: 3
```

Напишите боту `/start` — витрина готова, можно купить на Stars ⭐.

## Управление магазином из бота — `/admin`

Витриной управляют **прямо в Telegram**, не редактируя JSON руками. Отправьте
боту `/admin` (доступно только id из `WAVE_ADMIN_IDS`) — откроется панель:

- **🛍 Товары** — список; у каждого ✅/⛔ (виден/скрыт). Тап по товару →
  карточка: скрыть/показать, поменять цену, поменять выдачу или пополнить склад,
  удалить.
- **➕ Добавить товар** — пошаговый мастер: название → описание → цена (₽; Stars
  пересчитываются сами) → тип. Тип `мгновенная выдача` спросит текст, который
  придёт покупателю после оплаты; тип `ключ со склада` заводит товар, склад
  пополняется отдельной кнопкой.
- **💰 Выручка** — сумма ₽ и число оплаченных заказов.
- **🏦 Кассы** — какие способы оплаты включены.

Мастер держит состояние в памяти (бот однопоточный — это безопасно). Выйти из
мастера в любой момент — `/cancel`. Новый товар появляется на витрине **без
перезапуска** бота: каталог перечитывается с диска на каждый запрос.

**Тесты:** `python3 tests/admin_panel_v1.py` (22 проверки: CRUD, мастер обоих
типов, доступ только админу, парс «1 600 ₽», удаление с подтверждением).

## Операторская панель (M5)

**WAVE Control Room** — read-only панель для оператора:

```bash
# Запуск (порт 8792, localhost-only)
WAVE_CONTROL_TOKEN=ваш_секрет python3 control_room.py
```

Открываете `http://127.0.0.1:8792`, вводите токен — видите:
- **Выручку** (₽, число оплаченных заказов, начисления рефералам)
- **Кассы** (какие включены: Stars / ЮKassa / Крипта / Ручная)
- **Склад** (остатки ключевых товаров, бесконечные — маркер ∞)
- **Заказы** (последние 40, id/товар/касса/сумма/статус/когда)
- **Ключи шлюза** (выданные `wave-...` токены — ЗАМАСКИРОВАНЫ до последних 6 символов, квота/остаток/состояние)
- **Подписки** (товар/сумма/авто или ручное продление/срок)

**Закон панели:** она НИЧЕГО НЕ ДВИГАЕТ. Только читает локальные JSON. Ни одной записи, ни одного списания, ни одного обращения к Telegram/провайдерам — чистая смотровая площадка.

**Доступ:**
- Слушает только `127.0.0.1` (задать `WAVE_CONTROL_HOST` осознанно).
- Требует секрет `WAVE_CONTROL_TOKEN` — без него генерирует разовый и печатает в консоль (открытый доступ к выручке недопустим даже на localhost).
- Токены клиентов **маскируются** — оператор видит состояние, а не сами ключи.

**Тесты:** `python3 tests/control_room_v1.py` (19 проверок, включая изоляцию токенов).

## WAVE GATEWAY — шлюз доступа к ИИ (главный узел)

Это то, что превращает **один твой API-ключ** в товар для многих клиентов —
не отдавая клиентам сам ключ.

```
клиент → [токен wave-...] → WAVE GATEWAY → [твой ключ] → провайдер
                                  ↓
                          учёт токенов + лимиты
```

**Зачем именно так, а не «дать ключ на 2-3 человека»:**

| Отдать свой ключ | Через шлюз |
|---|---|
| Клиент видит ключ → утечёт, перепродадут | Клиент видит только свой `wave-...` |
| Один циклер выжирает весь баланс | Суточный потолок режет на 10 млн |
| Непонятно, кто сжёг деньги | Расход по каждому клиенту точно |
| Отзыв ключа рубит всех сразу | Отключение одного клиента кнопкой |
| Почасовой тариф невозможен | Таймер на стороне шлюза |

### Запуск

```bash
# 1. Твой настоящий ключ — только в окружении, НИКОГДА в коде
export WAVE_UPSTREAM_KEY=sk-твой-ключ
export WAVE_UPSTREAM_URL=https://api.провайдер.com/v1

# 2. Шлюз (порт 8790)
python3 -m gateway.proxy

# 3. Кабинет клиента (порт 8791)
python3 -m gateway.dashboard
```

Клиент подключается как к обычному OpenAI API — инструкция в
[`CLIENT_SETUP.md`](CLIENT_SETUP.md) (Cursor, Continue, Python, JS, curl).

### Тарифная сетка — «один продукт, много смыслов»

Один и тот же доступ продаётся 9 способами под разные аудитории:

| Тариф | Цена | Кому |
|---|---|---|
| 🎁 Демо 24 ч | бесплатно | «сначала покажите, что работает» |
| ⚡️ Час / вечер / сутки | 550–4000 ₽ | «нужно на один вечер» |
| 📦 3 / 10 млн CAPS | 4800–15 800 ₽ | «куплю запас, срок — год» |
| 🔄 5 / 15 млн в месяц | 7900–23 700 ₽ | постоянная работа |
| 👑 Безлимит | 19 900 ₽ | вершина, максимальная маржа |

Сетка в `gateway/quota.py` → `PLANS`, цены витрины — в `data/catalog.json`.
Лимиты заданы в CAPS (взвешенные единицы: выход ×5, чтение кэша ×0.1) —
см. `gateway/pricing.py`. Прежде чем менять цену, прогоните `tests/pricing_v1.py`:
он не даёт тарифу стать убыточным при полном расходе квоты.

**Демо** — вход в воронку: один на аккаунт (замок в `issue_key`, не в UI),
только Sonnet (потолок модели проверяет прокси), в LEDGER не пишется,
реферальную награду не платит.

### Автопродление подписок

Подписки продлеваются **автоматически** через периодический прогон `renewals.py` из cron. Движок:
- Предупреждает заранее о предстоящем списании (за 3 дня, настраивается через `WAVE_RENEW_NOTICE_DAYS`).
- Списывает деньги по истёкшим подпискам с привязанной карты (безакцептно, клиент ничего не подтверждает).
- Продлевает срок от старого `paid_until` — клиент не теряет дни.
- Ставит на паузу после 3 провалов (карта отклонила списание).

**Идемпотентность:** если cron прогонится дважды по одной просроченной подписке — списания дважды не будет. Идемпотентность-ключ стабилен для одного периода: ЮKassa вернёт тот же платёж.

**Fail-soft:** одна сломанная подписка (exception) не убивает всю пачку — остальные клиенты продлятся нормально.

**Настройка:** см. [`CRON_SETUP.md`](CRON_SETUP.md) — добавляется одна строка в crontab (раз в час, минута выбрана не :00/:30 чтобы снять пик нагрузки).

### Тесты

```bash
python3 tests/gateway_v1.py     # 19: квоты, потолки, изоляция, защита ключа
python3 tests/pricing_v1.py     # 20: экономика — ни один тариф не убыточен
python3 tests/smoke_v1.py       # 17: путь покупки + защита от двойной выдачи
python3 tests/demo_v1.py        # 25: демо — один на аккаунт, гонка, потолок модели
python3 tests/renewals_v1.py    # 23: автопродление — деньги доходят до учёта, цена ключа не стирается
python3 tests/retention_v1.py   # 32: ключ не меняется, конфиг рабочий
python3 tests/control_room_v1.py # 19: операторская панель — изоляция токенов
python3 tests/dashboard_spend_v1.py # 26: кабинет клиента — расход в ₽ по его цене, взломать нечем
python3 tests/storefront_live_v1.py # 8: витрина на БОЕВОМ каталоге — товар покупаем
python3 tests/gateway_e2e_v1.py     # 12: СКВОЗНОЙ прокси живьём — стрим списывается ненулём, ключ не течёт
```

**Итого:** 201 проверка (10 наборов).

**Почему `storefront_live_v1.py` стоит особняком.** Остальные семь наборов
собирают свой временный каталог с `kind='key'`. Боевой `data/catalog.json`
состоит целиком из `kind='gateway'` — и магазин месяц простоял мёртвым (ни у
одного товара не было кнопки «Купить») при 153 зелёных проверках: наличие
считалось по складу у товара, у которого склада нет по устройству. Этот набор
берёт ровно те данные, которые увидит покупатель, и ничего не подменяет.
Правило: витрину проверяем на боевом каталоге, не на удобном тестовом.

### Удержание клиента — как это устроено

Три механики, каждая закрывает свою причину ухода:

1. **Ключ не меняется при продлении.** Клиент один раз вписал `wave-...` в
   Cursor — и больше не возвращается к настройкам. `_issue_gateway_key()` для
   повторяющихся тарифов вызывает `QuotaStore.extend()`, а не выдаёт новый
   токен. Новый ключ каждый месяц превращал бы продление в работу.
2. **Автоподключение** (`gateway/setup_kit.py`): бот присылает готовый конфиг
   под инструмент клиента — одна команда, ноль ручного ввода. Между «оплатил» и
   «получил пользу» не должно быть ручной настройки: каждый шаг там — место,
   где человек бросает уже после оплаты.
3. **Автопродление с честным рубильником:** карта привязывается при первом
   платеже, о списании предупреждают заранее, отключается одной кнопкой,
   оплаченный срок при отключении сохраняется.

## Кассы (добавляются поэтапно)

### Telegram Stars (⭐) — работает сразу
- **Что:** оплата внутри Telegram, без регистрации и сервера.
- **Настройка:** ничего. У товара укажите `"stars_price": 30`.
- **Вывод:** Telegram → Ads → ₽ на карту ([инструкция](https://telegram.org/blog/telegram-stars)).

### ЮKassa (💳 РФ-карты / СБП)
- **Что:** реальные ₽ сразу на твой счёт.
- **Нужно:** ИП или самозанятость, аккаунт [ЮKassa](https://yookassa.ru).
- **Настройка:** в `.env` добавь:
  ```
  WAVE_YOOKASSA_SHOP_ID=123456
  WAVE_YOOKASSA_SECRET_KEY=live_xxxxxxx
  ```
- Перезапусти бота → ЮKassa появится в списке способов оплаты.

### Крипта (🪙 USDT)
- **Что:** крипто-платежи через [@CryptoBot](https://t.me/CryptoBot).
- **Настройка:** получи токен у @CryptoBot (`/my_apps` → Create App), в `.env`:
  ```
  WAVE_CRYPTO_PAY_TOKEN=12345:AAxxxxxx
  WAVE_CRYPTO_ASSET=USDT
  ```

### Ручная оплата (🧾)
Покупатель переводит по реквизитам, админ подтверждает кнопкой `/confirm <order_id>`.
```
WAVE_MANUAL_PAY_DETAILS=Карта Сбер 1234 5678 9012 3456\nИмя Фамилия
```

## Админ-команды (в боте)

- `/admin` — **панель управления** (товары, добавить, выручка, кассы). Основной
  способ управлять магазином — см. раздел «Управление магазином из бота» выше.
- `/cancel` — выйти из мастера добавления/правки.
- `/stock <product_id> <ключ1,ключ2>` — пополнить склад командой (то же делает
  кнопка «склад» в карточке товара).
- `/confirm <order_id>` — подтвердить ручную оплату и выдать товар.

## Рефералы

Каждый клиент получает персональную ссылку `t.me/bot?start=ref_XXXX`. Приглашённый по ней покупатель → рефереру начисляется **10% с покупки** (из выручки магазина, не из кармана покупателя).

Баланс и статистика: кнопка «💰 Баланс и рефералы» в боте.

## Безопасность и закон

- **Только легальный товар:** то, чем ты владеешь или имеешь право перепродавать.
- **Честные цены:** не продавай то, чего нет на складе.
- **Никакого обхода** анти-фрода сервисов, перепродажи чужих API-ключей, фарма.

Канон MINT: **закон > прибыли**.
