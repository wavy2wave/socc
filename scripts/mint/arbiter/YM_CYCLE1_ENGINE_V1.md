# YM_CYCLE1_ENGINE_V1 · ДВИЖОК ЦИКЛА-1 «Идея → Товар → Витрина»

> Артефакт = **ТОВАР НА ВИТРИНЕ** (PUBLISHED + available + остаток FIT). Движок выражает
> ДОКАЗАННЫЙ ручной проход 2026-09-02 (плёнка ARB-*, кабинет Atlas 216949599 / Express 149215943 /
> склад 2390811) как законную цепь узлов. Рядом: `YM_CYCLE1_V1.md` (канон), `ymarket_cycle1_v1.py` (код).

## 1. Идея: цикл — это цепь узлов, а не скрипт-файл

Ручной проход (утро 2026-09-02) был **последовательностью легальных действий**, каждое — с
доказательством чтением живого состояния. Движок не «вызывает функции» — он исполняет **цепь узлов**
с законным PASS-гейтингом:

```
ДОНОР → СБОРКА → ЗАЛИВ → ВИТРИНА → ОСТАТКИ → СВЕРКА → ПЛАНЁРКА
 0₽GET    локально  content   placement   stocks    READ     самоосознание
                    write      write      write     (всегда)
```

**Закон L12 (НЕТ fake pass):** узел N+1 стартует только после `PASS` узла N. `FAIL` любого узла —
ОСТАНОВ цепи: леджер пишет причину, пульс красный, планёрка завтра покажет. Никто не «переходит
дальше по-тихому». `СВЕРКА` — отдельный узел-чтение, он работает **всегда** (и в dry): `200 OK` от
писателей врёт, правда — в `campaign_offers`/`stocks`/`offer-mappings`.

## 2. Манифест магазина (L13: задачи, не вопросы)

Канонический вход для **каждого** магазина — `runtime/cycle1/stores.json`. Манифест решает, что
делать; оператор отвечает только на вход (один раз на магазин):

```json
{
 "atlas-express-film": {
   "slug": "atlas-express-film",
   "business_id": 216949599,     "campaign_id": 149215943,   "warehouse_id": 2390811,
   "donor_category": "vozdushno-puzyrkovaya-plenka",
   "builder": "film",            "builder_slug": "puzyrkovaya-plenka",
   "markup": 8.0,                "stock_count": 100
 }
}
```

| поле | что это | откуда |
|---|---|---|
| `slug` | короткое имя магазина | оператор |
| `business_id` / `campaign_id` / `warehouse_id` | кабинет / ЭКСПРЕСС-витрина / склад | кабинет партнёра |
| `donor_category` | категория донора (URL-путь `suppliers/*_v1.py`) | донор |
| `builder` | сборщик полной карточки (`film` = `film_cards`) | наш рецепт |
| `markup` | **цена = закупка × markup** — владелец ЦЕНОВИК (L9) | оператор/ОЧКИ |
| `stock_count` | остаток на витрине (L3: донор-real или слово оператора, НЕ выдумываем) | оператор/донор |

**Ключ API — только из env** (`YANDEX_MARKET_API_KEY`), в манифест секреты не пишутся (RUBICON).
Если манифеста нет — движок честно печатает список недостающих полей и пример, **не** задаёт вопросов.

**Хеш цикла** = `sha1(slug × дата × версия цепи)[:10]` → 10/100 магазинов живут параллельно, каждый
со своим леджером и пульсом, ни один не мешает другому.

## 3. Узлы (что делает, чем доказывает PASS)

| узел | действие | write? | PASS = |
|---|---|---|---|
| **ДОНОР** | живой скан категории донора (0₽ GET), ОВХ-обогащение габаритов посылки | нет | ≥1 строка скана |
| **СБОРКА** | рецепт builder: факты донора → `_spec` (13 параметров кат. 76346336) + наше HTML-описание + ОВХ + СВОЙ EAN + фирменное фото | нет | все карточки полные, фото на месте |
| **ЗАЛИВ** | content-only: `create_card` (offer-mappings гейт → offer-cards) | да | нет ошибок по всем SKU |
| **ВИТРИНА** | `place_in_campaign available=True` (магазин включён в кабинете) | да | нет ошибок |
| **ОСТАТКИ** | `update_stocks` FIT на склад манифеста | да | ok по всем SKU |
| **СВЕРКА** | ЧТЕНИЕ `campaign_offers`+`offer-mappings`+`stocks`: PUBLISHED+available+остаток+vendor «Без бренда» | нет | ВСЕ SKU на витрине |
| **ПЛАНЁРКА** | вчерашний леджер + этот прогон → `last_pulse.json` | нет | нет FAIL за прогон |

RUBICON (L6): **write-узлы шлют в сеть ТОЛЬКО когда `--commit`**; в `--dry` они возвращают
`DRY` — «точный payload собран и прошёл гейт, НЕ отправлен» (0₽ наружу, честно помечено).

## 4. Пульс и леджер (самоосознание L14)

- **Леджер**: `runtime/cycle1/<slug>/<YYYY-MM-DD>.jsonl` — по строке на каждый узел
  `{node, verdict, note, ms, ts, evidence}`. Пишется append **после каждого узла** — планёрка читает
  даже оборванный прогон. `runtime/` gitignored (не утечёт в GitHub).
- **Пульс**: `last_pulse.json` — счётчики вердиктов сегодня/вчера, по узлам, число артефактов-СВЕРКА.
- **Терминал**: живая ANSI-строка на узел `✓/✗/◌`, хеш прогона, итог:
  - `■ ЦИКЛ-1 ЗАКРЫТ` — все PASS с доказательством (артефакт на витрине),
  - `■ DRY-ПРОХОД ЧИСТ` — узлы готовы, для живого хода `--commit`,
  - `■ ЦИКЛ ОСТАНОВЛЕН на «NODE»` — чинить и перезапускать, без fake pass.

## 5. CLI

```
python3 ymarket_cycle1_v1.py                          # dry, магазин atlas-express-film
python3 ymarket_cycle1_v1.py --store <slug> --dry     # явный сухой ход 0₽
python3 ymarket_cycle1_v1.py --store <slug> --commit  # ЖИВОЙ ход (по слову оператора)
python3 ymarket_cycle1_v1.py --store <slug> --plenerka  # только пульс (утренний узел)
python3 ymarket_cycle1_v1.py --store <slug> --verbose  # полный поток узлов (payload) — по умолчанию ТИХО
```

**ТИХО по умолчанию (эпоха УПРАВЛЯЮЩЕГО-МОЗГА):** «многа букав» убрана — каждый узел исполняется под
захватом stdout, наружу идут только пульс-строки и вердикт. Полные payload (из `ymarket_write_v1._dry`)
появляются лишь с `--verbose`. Честность FAIL сохранена: при ошибке узла показывается хвост захваченного
вывода (~14 строк). Законы L6/L12/L14 не изменились.

**МАМА-НАСЛЕДОВАНИЕ (кабинет-agnostic вход):** манифест нового магазина может опустить
`business_id/campaign_id/warehouse_id` и указать `"mother": "<slug>"` — движок наследует кабинет от
глубочайшей мамы по цепочке (`resolve_profile`, защита от циклов; поля ребёнка приоритетнее). Товарные
поля (донор/builder/markup/остаток) — свои у каждого цикла, не наследуются. Хелперы-реестры:
`list_cycles()` (глаза мозга), `add_store(profile)` (валидированная запись; без mother и кабинета —
авто-мать `STORE_DEFAULT`). См. `YM_BRAIN_V1.md` §6.

## 6. Автопилот (24/7 сухо, план)

Вахта по внедрению:
1. launchd-плитку на `--plenerka` утром (узел самоосознания пишет пульс в ТГ, когда токен ТГ будет).
2. `--commit` ЦИКЛА-1 вешает ТОЛЬКО вахта после слова оператора на живом кабинете.
3. Новый магазин = новый блок в `stores.json` (другой bid/cid/wh/донор/builder/markup/остаток) —
   движок и хеш-адресация позволяют **10–100 циклов параллельно** без правки кода.
4. Новый builder (коробки/другая категория) = свой рецепт по образцу `film_cards.build_product`
   + `brand_law` — фото-слой из фото-органа, индекс-рычаг свой EAN + «Без бренда» (L8).

## 7. Законы, которые движок исполняет (канон §13)

L6 RUBICON · L8 Бренд = «Без бренда» (YM не индексирует незарегистрированное) · L9 цена = владелец
ЦЕНОВИК, MARKUP из манифеста, в акциях товар НЕ участвует · L10 ОВХ = правдивая транспортная упаковка
с карточки донора · L11 фото: товар + фирменная инфографика (color-science), карточка без фото = FAIL ·
L12 НЕТ fake pass · L13 задачи, не вопросы · L14 планёрка = самоосознание.
