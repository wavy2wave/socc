## A0. ТОЧНЫЙ ДИАГНОЗ (уточнён по коду, а не по памяти)

Ранее я сформулировал дефект как «доставка нигде не вычитается». **Это было неточно.**
Прочитав `arbiter_batch_v1.py` и `pricing_v1.py` целиком, вижу настоящую механику:

**Путь охоты доставку ЗНАЕТ.** `best_multiple` (`arbiter_batch_v1.py:347-351`) передаёт
`pricing={"delivery": delivery, ...}` → `gap._price_gate:185-195` → `decide_price(delivery=...)`
→ `guaranteed_profit:67` вычитает `dlv`. И `hunt_category:403` берёт `net = p.get("profit_net")`
из **price**-словаря, то есть число победителя — доставку учитывает.

**А вот ГЕЙТ — не знает.** В `gap_v1.prove:239`:

```python
verdict = "PROVEN" if (econ["passed"] and pnet >= float(min_profit)
                       and ward["status"] == "PASS") else "REJECTED"
```

где `pnet = econ["margin"]["profit_net"]` — из `compute_margin:38`, **без доставки**.

### Настоящий дефект, одной фразой
> **Порог `min_profit=200` применяется к числу, которое игнорирует ₽325 издержек.**

Ценовой гейт (`prove:247`) режет только `profit_net <= 0`. Значит связка, у которой
delivery-слепая прибыль ₽210, а реальная +₽1 — **проходит как PROVEN «чист ₽210»**.
Порог не то что мягкий — он меряет не ту величину.

### Второй дефект: одно имя, два числа
В выдаче `prove()` живут одновременно:
- `econ.profit_net` — **без** доставки (по нему решается вердикт и печатается CLI `gap_v1:372`)
- `price.profit_net` — **с** доставкой (по нему ранжируются победители батча)

Оба называются `profit_net`. Читатель не может знать, какое он держит.

### Третий: `find_gaps`/`scout_gap` без `pricing`
`gap_v1:313-326` и `:329-340` не принимают и не передают `pricing` → на этом пути
ценового гейта **нет вообще**, значит нет и delivery-осведомлённого числа. Единственная
защита — тот самый слепой порог. Это путь CLI `gap_v1 --query`.

### Четвёртый: `DEFAULT_DELIVERY = 100.0`
`arbiter_batch_v1.py:66` — живая голова, при факте кабинета ₽325.
`DELIVERY_NET = 325.0` (`socc_mint_prospect_v1.py:21`) — правда без потребителей.

### Пятый: устаревшие комментарии врут о константе
- `pricing_v1.py:52` — `DEFAULT_NET_COEFF = prospector.NET_COEFF   # 0.35` (значение уже 0.298)
- `pricing_v1.py:21-24` — весь пункт 3 шапки про «65% / NET_COEFF=0.35»
- `arbiter_batch_v1.py:7,19,73,86-90,199` — «65%», «35%», доставка ₽100 в примерах и в отчёте
- `arbiter_batch_v1.py:143` и `gap_v1` honesty-строки — «комиссия Озон 65%»

Это не косметика: строка `honesty` уходит в JSON-слепки и в канон. Ложь про метод
консервируется в артефактах.
