## 0. Позиция

Цикл-1 = первый из циклов ARBITER, доводящий товар до **ЖИВОЙ ВИТРИНЫ** на Яндекс Маркете (Экспресс). Это не новый орган — это **рамочный план**, который связывает уже построенные органы в один суточный конвейер с КПИ и артефактами.

**Почему Цикл-1, а не «всё сразу»:** у нас уже доказано (сухо, 0₽, RUBICON цел) ~250+ приёмок через 20+ раннеров. Не хватает не механизмов, а **результатов наружу**: товар, который ВИДЕН на витрине, покупаем, и у него есть номер заказа. Цикл-1 замыкает 8 ступеней канона в один отчётный виток.

**Модель сбыта (доктрина):** FBS Экспресс — курьер Яндекс Маркета забирает у донора по внутреннему № заказа. DBS НЕ нужен (опровергнуто оператором, см. канон). Живой кабинет: biz 184481130, магазин FBS Express 148619267, склад 1803385 (express=True; резерв 1652222). Тест: biz 216949599, Express 149215943, склад 2390811 «Атлас» Москва, Вавилова 9Ас8.

**Две линии Claude (не трогать чужое):**
- Эта линия — канон Цикл-1, база «торговая точка», матрица товаров, планёрка, КПИ, фото-орган (photo_hunter — ковали здесь по приказу).
- Параллельная — `ymarket_write_v1` + `ymarket_runner_v1` (СВЕРКА), forge/pipeline/publish. Здесь читаем, не перековываем.

**RUBICON (железно):** наружу только READ (0₽) и dry. WRITE = только `not dry AND commit`, и только по слову оператора. Выкуп у донора ТОЛЬКО после уже-оплаченного заказа. Никогда не закупаем заранее.

## 1. Структура Цикла-1

Цикл-1 = ступени 1–6 канона ARBITER (8 ступеней). Ступени 7–8 (ПРОДАЖА→ВЫКУП→ОТГРУЗКА, УЧЁТ+РОСТ) живут как Цикл-2/Цикл-3, но шов выкупа (`bridge`+`buy_adapter`, M3/M4, зелёные) уже готов.

**Ступени Цикла-1 → артефакт:**

| # | Ступень | Орган | Артефакт (видимый) |
|---|---------|-------|--------------------|
| 1 | ВЫБОР (идея) | Шлюз добычи: WB / партнёр-сайты (задания) / планёрка | Список кандидатов + источник + причина |
| 2 | СБОРКА | КАТЕГОРИЙЩИК + ТОВАРОВЕД + ФОТО-ОРГАН | Сухая партия: готовые к заливу позиции |
| 3 | ЗАЛИВ | `publish_card` (4 API-шага) | Карточка в каталоге кабинета |
| 4 | СВЕРКА | `reconcile`/runner | Вердикт: карточка чистая, не frozen |
| 5 | ТОП | ОВХ-слой + dense характеристики | content_rating растёт (цель 80%+) |
| 6 | **ВИТРИНА ЖИВАЯ** | `update_stocks` (остаток) | **«В НАЛИЧИИ НА МАРКЕТЕ» — товар покупаем** |

**Артефакт Цикла-1 = товар на витрине.** 1 товар = 1 артефакт. 100/1000 = следующий артефакт. Каждый товар на витрине математически поднимает вероятность заказа.

**Под-циклы 1.1–1.6** (суточные дышащие петли внутри):
- **1.1 Добыча** — шлюз (см. §2 «Шлюз»)
- **1.2 Сборка сухая** — категорийщик + мост залива + фото-слой (провязано, 53/53)
- **1.3 Залив** — publish_card (4 шага, живые уроки Atlas Edge)
- **1.4 Сверка** — reconcile/runner
- **1.5 Рост качества** — ОВХ + характеристики + фото
- **1.6 Остатки→витрина** — update_stocks (донор-real остаток, НЕ выдумывать)

## 2. Шлюз добычи товара

Три источника, ОДИН вход. Брать ТОЛЬКО WB = критическая ошибка (директива).

1. **WB** — источник №3. Даёт РЕФЕРЕНС (что за товар, размер, цена), 0₽, 0 токенов. Фото WB = референс, НЕ чистый источник (впаянная инфографика конкурента — проверено: 0/10 чистых). Пиксели на карточку — НАШИ (см. §Фото).
2. **Партнёр-сайты** — задания оператора (рук. №): присоска SupplierAdapter (`suppliers/base_v1`, контракт `scan→normalized`). cargo-avto уже присоска. Детмир/Спортмастер/HOFF/4лапы — паспорт партнёра (см. законы потерь+партнёры).
3. **Планёрка** — самоопределение: новости/погода/тренды/сезон → «сегодня охотимся за X». Первый снег → лопаты/соль, НГ → ёлки/фонарики. Должно быть схвачено.

**Правило связки (директива №5):** заводим категорию = магазин уже проверен (гейт канона). Артикул ↔ АртикулМагазина ↔ Магазин фиксируется в реестре (`ymarket_registry_v1`, R1–R6) — прямая ссылка на товар в момент заказа.

## 3. Органы Цикла-1 · задания · КПИ · артефакты

| Орган | Задание (24/7 если не указано) | КПИ | Артефакт |
|-------|-------------------------------|-----|----------|
| **КАТЕГОРИЙЩИК** | Сканирует доноров, ранжирует, копит категории | ≥5 новых категорий/день; 0 выдуманных данных (needs_data честно отделён) | Подтверждённая категория + шорт-лист (плёнка: маркет_category_id 76346336; короба: 76296786) |
| **ЦЕНОВИК** | Предлагает цену продажи ×5–10 от закупки, пол-маржи не даёт просесть | Средняя предложенная маржа (макс.); не ломается на сложных товарах | Цена с обоснованием (характер: ломает шаблоны — плёнка 1.2×50 покупается дорого, у людей так) |
| **ФОТО-ОРГАН** | hunter (0₽, ищет референс) → pipeline (pHash-закон) → forge (свои пиксели, ATLAS EDGE белый 4:5) → publish (свои-пиксели-гейт) | no_pictures → 0 у отобранных; свои фото = своя цена, карточки НЕ связываются | Свои пиксели под карточку |

| **АНАЛИТИК** | Планёрка: новости/погода/тренды/сезон → осмысленные задания | Схвачено всё (не слепой обзор) | Список заданий дня с причиной |
| **УПРАВЛЯЮЩИЙ** | Сводит утренний отчёт (KPI + дельта + что горит + куда растём) | Отчёт в ТГ каждый тик | Живой диалог в @yandexcrew_bot |
| **КОНТРОЛЁР** | quality_index: <40 → отключение на 7 дней, <98 → штрафы | index ≥40; cards_errored → 0 | Вердикт здоровья витрины |

**Суточный КПИ Цикла-1 (директива №16):** **500–1000 товаров/день** суммарно из разных источников/городов/магазинов. Цикл-1 считается закрытым, когда **≥5 категорий добавлено** и витрина живая.

**ТИК = РЕЗУЛЬТАТ.** Пустой тик (heartbeat) = не тик. Каждый тик обязан произвести артефакт ИЛИ названную причину, почему артефакта нет (блокер с владельцем).

## 4. База «торговая точка» (паспорт склада)

**Зачем (директива №7):** склад в кабинете заполнен как на сайте, профессионально, чтобы курьер приехал куда надо и не задал вопросов. Это «магия по сути» и всё реально работает.

**Что создаём (новый слой, надстройка над реестром):**
- Реестр уже хранит `offerId ↔ marketSku/shopSku/donor_pid/donor_url/source_url/supplier` (R1–R6). НЕ хватает **точки**: адрес, телефон, инструкция курьеру, warehouse_id, город, статус.
- Паспорт точки: `ТОВАРНАЯ_ТОЧКА` = {
  `point_id`, `shop` (cargo-avto …), `warehouse_id` (1803385 express=True …), `city` (Москва …),
  `address` (берём ЖИВЫМ из кабинета: `resolve_pickup` уже читает Express-адрес, не хардкодим),
  `phone` = **8 977 962 91 25 (склад оператора)**,
  `courier_instruction` = «Курьер звонит, ЖДЁТ № внутреннего заказа из магазина, входит как клиент, забирает мой заказ, доставляет как Яндекс Маркет»,
  `contact`/`hours`, `status` (active/draft)
}
- Привязка: `артикул ↔ артикул_магазина ↔ точка` — прямая ссылка на товар в момент заказа (без неё Экспресс не исполнить).

**Почему Express — честная модель:** клиент оплатил → оператор ~1 мин заказывает на cargo-avto с клиентских денег → курьер ЯМ забирает у донора по внутреннему №. Выкуп ТОЛЬКО после оплаченного заказа (доктрина, железный закон). Express = мгновенный пикап ~2ч, без платных парковок/лабиринтов, офлайн-магазины со своей доставкой по России.

## 5. Матрица товаров

**Зачем (директива «не повторяемся»):** чтобы не заливать одно и то же дважды и не плодить дубли-ошибки.

**Матрица** (таблица/реестр, НЕ дублирует `ymarket_registry`):
- Ключ дедупа: `article | EAN | name+размер` (нормированный) → `offerId` → `провайдер` (cargo-avto / WB / партнёр) → `категория` (cats JSON) → `статус` (кандидат/собран/залит/сверен/на-витрине/продан — ключи как в ymarket_matrix_v1).
- `заданиеId`: каждая задача имеет номер (директива). Матрица ссылается на задание → на категорию → на партию → на точку.
- Закон: позиция, уже находящаяся в «залит/на витрине», в добычу не возвращается (дедуп по формуле, 0 дублей).

## 6. Планёрка (утро)

**Что:** утренний осознанный ритуал — день недели, погода, новости, тренды, сезон → задания дня → артефакты. Не слепой обзор, а СМЫСЛ (первый снег → лопаты/соль; НГ → ёлки/фонарики; всё схвачено).

**Где:** видно в ТГ (@yandexcrew_bot). Оператор хочет видеть **рассуждение в диалоге**, живой и интересный — как команда думает, а не сухие строки.

**Формат планёрки (одна смена = один блок):**
1. Контекст дня (погода/новости/тренды/сезон).
2. Решения: что берём в работу, почему (причина на каждый выбор).
3. Задания с номерами (заданиеId) + владелец-орган.
4. Артефакты вчера/сегодня (счётчик).

**КПИ планёрки:** «всё схвачено» — список сезонных охот не пустеет, каждое задание имеет артефакт-цель.

Новые законы (прямая директива оператора, записываем, чтобы НЕ проходить руками заново):
- **L8 БРЕНД:** ЯМ НЕ индексирует незарегистрированный бренд — «ATLAS EDGE» не в реестре Маркета,
  поэтому «+2 за бренд» в индекс невозможен, а карточка без читаемого бренда не подгружается.
  Ставим каноническое **«Без бренда»** (эталон 99 баллов): закрывает обязательное поле, не раскрывает
  донора, не склеивает. no-brand = бренд НЕ заявляем НИГДЕ: поле, имя, описание. Отвязку от донора
  делает СВОЙ EAN-13 (главный рычаг), а не бренд.
- **L9 ЦЕНА:** владелец цен в цикл-1 = **ЦЕНОВИК/ОЧКИ** (реверс-ценовик: закупка донора → цена под
  фикс-profit, издержка-буфер всегда в расходе, потолок ×8). Цена продажи = закупка ×MARKUP (плёнка
  ×8, TUNABLE подтверждён). **ТОВАР НИ В КАКИХ АКЦИЯХ** в цикл-1 — никаких скидок/промо-кампаний;
  орган акций будет пробовать стратегии ОТДЕЛЬНО и ПОЗЖЕ. Целимся в индекс карточки 80–90–100.
- **L10 ОВХ (габариты/вес):** только **транспортная упаковка** — то, что уйдёт курьеру; правдивые,
  снятые с карточки донора ОВХ-слоем (см→×10→мм), не выдумываем и не округляем в «красивость».
  Все 4 плёнки (50×35×50 / 30×48×48 / 75×38×38 / 40×11.5×11.5 см) = транспортные коробки донора.
- **L11 ФОТО/ИНФОГРАФИКА (дизайн SOCC):** на кадре НИЧЕГО лишнего — только ТОВАР + наша фирменная
  инфографика. Инфографика несёт **конверсионную** информацию (что заставит купить сразу: плотность,
  площадь, толщина…) — берём из изучения карточек WB/конкурентов, НЕ с потолка. Цвета ИМЕЮТ СМЫСЛ:
  цветовая кодировка типа товара (ширина, слои, категория) + наука цвета в дизайне (воздействие на
  психику/конверсию). Шаблон = АРТЕФАКТ органа: плёнка — один шаблон, короба — другой, собираем
  коллекцию. Узнаваемость = наше преимущество, качаем.
- **L12 НЕТ FAKE PASS:** узел N+1 стартует ТОЛЬКО после законного PASS узла N с доказательством
  (чтение живого состояния, не вера ответу записи — 200 OK врёт). Когда PASS все — система закрывает
  цикл. Цикл-1 закрыт не «по словам», а по артефакту на витрине.
- **L13 TASKS, НЕ ВОПРОСЫ:** органы исполняют ЗАДАНИЯ (что делать → планировщик/орган-задачник),
  цикл НЕ задаёт вопросов оператору на каждом шаге — он знает что делать по цепочке заданий.
  У каждого органа потолок дня → премия/эволюция за проявленность.
- **L14 ПЛАНЁРКА = САМООСОЗНАНИЕ:** утренний узел собирает вчерашние артефакты/отчёты всех органов в
  ПУЛЬС системы (реальные показатели, не цифры ради цифр). Это не болтовня — это место, где система
  видит, жива ли она и куда идёт.
