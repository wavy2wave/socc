# SEED канон донора · почему эти файлы В git

Приёмки гейта «не с неба» (`run_ozon_donor_anchor.py`, `run_library.py`) читают канон
донора с диска. Без него на **свежем клоне** машина краснеет — хотя на машине оператора
всё зелёное (файлы лежат локально, просто не трекаются).

Баг найден 2026-09-16: чистый клон `/tmp/socc_fresh` → 6 FAIL из 71.

## Что здесь и почему это можно в git

| файл | что | почему не секрет |
|---|---|---|
| `donor-rolls-2026-09-09.json` | 39 рулонов донора (артикул, url, w/l/dens/lay, cost) | публичный каталог cargo-avto |
| `donor-size-map-2026-09-08.json` | карта размеров | производное от публичного |
| `donor-reconcile-2026-09-09.json` | свёрка библиотеки (kept/changed/new) | внутренняя сверка, ПДн нет |
| `library-2026-09-08.json` | библиотека 844 строк | публичные данные поставщика |

Проверено гейтами `make secrets` и `make pii` — чисто.

## Что здесь НЕ живёт (M3)

`content-rating-*`, `donor-anchor-*`, `donor-linkage-verdict-*`, `file-rows-*`,
`file-pour-library*`, `*.bak-*` — тяжёлые производные артефакты живых прогонов.
Пересоздаются органами, в git не нужны.

## Обновление сида

При изменении канона/библиотеки константы D8 в `run_ozon_donor_anchor.py` обновлять
**честно, не подгонкой** (закон самой приёмки).
