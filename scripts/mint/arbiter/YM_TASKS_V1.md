# YM_TASKS_V1 · SOCC-ЯМ · РЕЕСТР ЗАДАНИЙ ЦИКЛА (durable-журнал работ)

> Директива оператора 2026-09-02 («доп задание», ЯМ ЦИКЛ): «Есть задания … У задания есть ХЕШ.
> Хеш показывает что для чего, от кого, срочность и само задание. Задания распределены по
> категориям, важные — выше списка. У задания всегда есть ответственный орган (удавка на него).
> Пункты закрываются по правилу "проверили без фейк-пасс → пункт выполнен → идём дальше
> последовательно". Формат универсальный — всегда для ЯМ и ОЗОН».
> Рядом: `ymarket_tasks_v1.py` (ядро), `tests/run_tasks.py` (приёмка TZ1–TZ13).
> Фундамент, на котором заработают ЦИКЛ-ДНЯ (диспетчер), планёрка и терминал ЯМ-ЦИКЛ.

## 1. Мандат

Система не стоит: **задания всегда существуют и всегда формируются** — это запал и работа живого
цикла. ЦИКЛЫ (ЦИКЛ-1/ЦИКЛ-2/ЦИКЛ-ДНЯ) их подхватывают. Реестр — durable-место, где живёт каждое
задание: для чего (what), от кого (source), срочность (urgency), что именно (what+steps), кому
(owner — «удавка на него»), в каком состоянии (по ПУНКТАМ, без фейк-пасс). Один формат для ЯМ и
ОЗОН (market) — «системный законный АГИ-язык», будущий ЦИКЛ ОЗОН ест тот же реестр.

## 2. Законы (TZ1–TZ13)

| # | закон | как исполняется |
|---|---|---|
| TZ1 | **id = стабильный хеш намерения** | `task_id = "T-" + sha1(market·cycle·category·store·what·owner·urgency)[:8]`. То же намерение, сформированное снова, — тот же id: реестр ОБНОВЛЯЕТ запись, не плодит дубль. |
| TZ2 | **одна схема ЯМ+ОЗОН** | `market ∈ {ym, ozon}`; структура записи ОДНА (АГИ-язык). ЦИКЛ ОЗОН не переизобретает реестр. |
| TZ3 | **цикл подхвата обязателен** | `cycle ∈ {cycle1, cycle_day, cycle2}`. Задание без цикла — «в стол»; система стоит — запрещено. |
| TZ4 | **магазин необязателен** | общесистемные задания без store валидны; привязанные к кабинету — с store=slug. |
| TZ5 | **владелец обязателен** | без owner задание не создаётся: у каждого задания есть ответственный орган («удавку на него»). |
| TZ6 | **срочность из словаря** | `critical/high/normal/low`; не задана → `normal` (честный дефолт); битая → отказ. |
| TZ7 | **важное выше списка** | сортировка планёрки: `priority` (меньше = важнее) → ранг срочности → created_at. |
| TZ8 | **пункты + гейт БЕЗ фейк-пасс** | новое задание: все пункты `open`. `mark_step` закрывает пункт ТОЛЬКО с непустым `evidence` и `done_by`. Задание `done` = ВСЕ пункты ● с фактом. Закрытое задание не трогаем (done-гейт). |
| TZ9 | **зависимости блокируют** | пока `depends_on` не в `done` — задание `waiting`, не «в работе». |
| TZ10 | **честная загрузка** | битого стора нет/не читается → `[]` + `load_error`; не падаем, не выдумываем. |
| TZ11 | **валидация ловит битое** | `validate()` возвращает список проблем (нет пунктов/market вне словаря/…); пусто = валидно. |
| TZ12 | **рендер для терминала** | `render_plannerka` = что оператор видит (иконка состояния · P-важность · магазин · what · владелец · категория · цикл · пункты N/M · id); `stats` = счётчики ЦИКЛ-ДНЯ. |
| TZ13 | **roundtrip без потерь** | save→load сохраняет пункты/evidence/state/owner; запись под flock+backup паттерном библиотеки. |

## 3. Запись задания (одна структура = «хеш показывает»)

```jsonc
{
  "id": "T-f74dd40f",        // стабильный хеш намерения (TZ1)
  "market": "ym",            // ym|ozon (TZ2)
  "cycle": "cycle_day",      // какой цикл подхватит (TZ3)
  "store": "ndj",            // кабинет или "" (TZ4)
  "category": "categories",  // partners|categories|products|cards|photos|pricing|promo|stocks|health|day|other
  "owner": "CATEGORIST",     // орган-ответственный — «удавка» (TZ5)
  "urgency": "high",         // critical|high|normal|low (TZ6)
  "priority": 10,            // меньше = важнее — важное выше (TZ7)
  "what": "Добавить категории из магазина NDJ (донор NDJ)",
  "body": "зачем/обоснование",
  "source": "partners",      // кто породил: operator|brain|cycle_day|partners|pricer|…
  "steps": [{"id":"s1","title":"…","state":"open","done_by":"…","evidence":"…","done_at":"…"}],
  "depends_on": ["T-…"],     // готово-первым (TZ9)
  "state": "open",           // open|in_progress|waiting|done|blocked|archived
  "refs": {}, "created_at": "…", "updated_at": "…"
}
```

## 4. API (чистые функции, dry, 0₽)

| функция | что делает |
|---|---|
| `new_task(what, owner, category, …)` | создать; битые аргументы → `(None, проблема)` честно |
| `validate(task)` | список проблем записи |
| `derive(task, done_ids)` | состояние из пунктов+зависимостей (TZ8/TZ9) |
| `mark_step(task, step, done_by, evidence)` | закрыть пункт ПОД гейтом (без факта = отказ) |
| `reopen_step(task, step)` | пересмотр пункта (не из done/archived) |
| `done_ids_of(tasks)` | id закрытых — для зависимостей |
| `sort_tasks(tasks)` / `by_owner/by_category/by_store/by_market/by_state/open_only` | планёрка и фильтры |
| `stats(tasks)` | счётчики ЦИКЛ-ДНЯ (total, %done, по категориям/владельцам/магазинам, срочные) |
| `render_plannerka(tasks)` / `render_task(task)` | что видит оператор/терминал |
| `load()/save(tasks)` | стор `MEMORY_WAVE/reports/mint/arbiter/ymarket_tasks.json`, env `YM_TASKS_PATH` перекрывает |

## 5. Место в ряду (что реестр НЕ дублирует)

| орган | роль | реестр |
|---|---|---|
| мозг `ymarket_brain_v1` | `[ДЕЙСТВИЕ]` одноразово, без состояния | durable: владелец/состояние/пункты |
| team_feed | события ролей → ТГ | журнал РАБОТ, не событий |
| matrix | статус ТОВАРОВ (кандидат→…→продан) | статус ЗАДАНИЙ (открыто→…→закрыто) |
| kpi | дневной журнал метрик | работ, а не метрик |
| state/registry | рабочие наборы, offerId↔pid | что и кому делать |
| cycle1 engine | выполняет цикл по магазину | подхватывается заданием типа cycle1 |
| day_v1 | утренний отчёт/СТРАТЕГ/скаут (read+report) | диспетчер работ (берёт → гонит → ● по пунктам) |

## 6. ЦИКЛ-ДНЯ (диспетчер) — ПОСТРОЕН: `ymarket_cycle_day_v1.py`

Диспетчер над этим реестром: утро → планёрка (магазины + ОДИН блок заданий по важности) → берёт
открытые задания → разбор «кто исполнит». Задания **формируются из ЖИВЫХ наблюдений** (ценовик ниже
КПИ → RAISE; донор с неизученными категориями → CATEGORIST), а не из воздуха. ЦИКЛ-1/2 смотрят сюда же:
реестр — источник «что делать».

| закон | как исполняется |
|---|---|
| CD1 | **read-планёрка честна** | `plannerka_text()` различает «реестра ещё нет» ≠ «реестр пуст» ≠ «открыто N» (registry_status). |
| CD2 | **форма без commit не пишет** | `form(commit=False)` — только показать кандидатов; диск не тронут. |
| CD3 | **commit идемпотентен** | то же намерение снова → `dup`, 0 новых; id стабилен (TZ1). |
| CD4 | **один глобальный блок** | планёрка = пульсы магазинов + ОДИН блок ЗАДАНИЙ (не блок на магазин). |
| CD5 | **диспетчер без фейк-пасс** | `dispatch()` без `--cycle-dry` ничего не гоняет и не mark_step; прогон-подхват — только сухо и явным флагом; органа без исполнителя здесь называет честно. Пункт закрывает орган-исполнитель с evidence (TZ8). |
| CD6 | **единственный write** | локальный реестр под `form --commit`; наружу (сеть/кабинет) диспетчер не пишет. |

CLI: `python3 ymarket_cycle_day_v1.py` (планёрка) · `--form` (показать, что сформируется) ·
`--form --commit` (записать реестр) · `--dispatch [--cycle-dry]`. Формирование — из живых артефактов:
`runtime/cycle1/_card_costs.json` (закупка донора) + леджер магазина (витрина из ноты ЗАЛИВ).

В МОЗГЕ (`ymarket_brain_v1.py`): `/задания` = планёрка · `/задания --form [--commit]` = показать/
записать (commit — по слову оператора, НУЖНО СЛОВО иначе) · `/задания --dispatch` = разбор.
Алиасы: задача/задачи/дело/дела/tasks. Все 0₽, read; write реестра — локальный файл.

**RUBICON:** реестр/диспетчер сами ничего не выполняют и не пишут наружу. Запись стора — только под
правилом вызывающего (движок: не dry AND commit). Evidence рождается только из реального факта
(чтение/вердикт органа) — фейк-пасс механически невозможен (TZ8). Цены/карточки/остатки не трогает.
