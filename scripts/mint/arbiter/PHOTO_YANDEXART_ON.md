## Почему этот файл существует

15.09.2026 живой прогон кузницы дал **400 на всех трёх моделях**:

```
Your subscription end, your account are freezed until renew (24220501531)
```

Тариф VseGPT **Проф-3д кончился 11.09.2026** (был куплен 08.09). Каталог из 463 моделей

**потом — VseGPT Проф** под премиум-плечо (`gpt-image-2` 10₽, `nano-banana-pro` 29.9₽).

Код ветки `yandexart` **уже написан и протестирован** — регрессия `run_photoforge.py` 47/47,
включая F41–F47 (форма запроса, автодетект, сухой превью, живая генерация под моком,
леджер, отказ без ключа/каталога, дедлайн поллинга). **Правок кода не требуется.**

| роль | **`ai.imageGeneration.user`** (на каталог) |

Разрешённая неясность по роли: **`ai.art.user` в Yandex Cloud НЕ СУЩЕСТВУЕТ.** Проверено живьём
15.09 (`yc iam role list`, 733 роли) — верная роль **`ai.imageGeneration.user`**. Прежнее имя в
докстринге `_yaart_key` было взято из доков, которые к тому моменту переехали на `aistudio.yandex.ru`;
в коде исправлено.

⚠️ **Каталог в браузере оператора (`b1gemhhg3dd1q1is1ae9`) — ДРУГОЙ аккаунт.** Из CLI он не виден
(`yc resource-manager folder get b1gemhhg3dd1q1is1ae9` → `not found`). Провизьон сделан в аккаунте,
которым авторизован `yc` — это и есть дом ARBITER (там же бакеты карточек `atlas-edge-cards-3fc8cf`
и `tama-sessions`). Если понадобится каталог именно из браузерного аккаунта — там доступ выдаётся
заново, ключ оттуда в `.env` не подойдёт.

<details><summary>Как это делалось (для повторения в другом аккаунте)</summary>

1. **Каталог (folder)** — выбрать или создать. Скопировать **folder ID** вида `b1g...`.
2. **Платёжный аккаунт** — YandexART платный, генерация не пойдёт без активного биллинга
   с привязанной картой.
3. **Сервисный аккаунт** — создать в этом каталоге.
4. **Роль** — `ai.imageGeneration.user` на каталог.
5. **API-ключ** — создать ключ ИМЕННО у сервисного аккаунта (не OAuth, не IAM-токен).
   Секрет вида `AQVN...` показывает **один раз** — копировать сразу.

Команды (проверено, работают от владельца облака):

```
yc iam service-account create --name arbiter-art --folder-id <FOLDER>
yc resource-manager folder add-access-binding <FOLDER> \
   --role ai.imageGeneration.user --service-account-id <SA_ID>
yc iam api-key create --service-account-id <SA_ID>     # секрет в stdout — сразу в .env, потом НЕ логировать
```

⚠️ **При создании ключа не смешивать stderr в stdout.** `... 2>/dev/null | python - <<'PY'` —
здесь heredoc съедает stdin питона, JSON не читается, а секрет при этом уже выдан и потерян
(так был сожжён первый ключ). Секрет лучше писать в `.env` скриптом-файлом, а не через пайп.

</details>

## 2. Зарядить env

Файл: `SOCC/scripts/mint/.env` (gitignored — в git НЕ коммитить).

```
YAART_API_KEY=AQVN...        # секрет сервисного аккаунта из шага 1.5
YAART_FOLDER_ID=b1g...       # folder ID из шага 1.1
```

Алиасы `YC_API_KEY` / `YC_FOLDER_ID` тоже принимаются, но **не смешивай**: `YC_ACCESS_KEY_ID` /
`YC_SECRET_KEY` (это S3-статики для бакета карточек) на `foundationModels` дадут **401** —
кузница их намеренно НЕ берёт (изоляция органа, `photo_forge_v1._yaart_key`).

### И снять ловушку переключения

В `.env` сейчас стоит **жёсткий override**:

```
PHOTO_FORGE_PROVIDER=ru_openai
```

Он **перебивает автовыбор**: впишешь ключи YandexART, а канал молча не включится. Заменить на:

```
PHOTO_FORGE_PROVIDER=yandexart
```

(или удалить строку целиком — тогда автовыбор сам выберет yandexart, как только увидят ключ+каталог).
Доктор теперь об этой ловушке **предупреждает отдельной строкой**, молчать не будет.

```

    каталог ключа: b1g5h7fcnf2088bh0rsj (в .env: b1g5h7fcnf2088bh0rsj)
```

Строка `YandexART: ЖИВ` — не «ключ лежит в .env», а 0₽-зонд: шлём генерацию с заведомо ЧУЖИМ
каталогом. Живой ключ → 400 «does not match with service account folder ID» (шлюз сам называет
настоящий каталог, отсюда и сверка рассинхрона), мёртвый → 401. Кадр в этом исходе физически
невозможен → **0₽ по построению**.

Ключ при этом честно виден и в консоли: `yc iam api-key list --service-account-id ajenpj7mlbnve7dcv7k7`
показывает `LAST USED AT` — если после зонда там свежее время, значит запрос реально дошёл до API,
а не остался в коде.

Роль/ключ/каталог соврать не дадут — зонд бьёт тем же сетевым швом, что и живой кадр.
Достижимость хоста подтверждена: `llm.api.cloud.yandex.net` отвечает с этого egress
(405 на GET — норма, эндпоинт только POST).

## Честные оговорки (чтобы не было сюрприза)

- **YandexART — ART-модель, не фотореалистичный продуктовый рендер.** Для карточек МП она
  может уступать премиум-плечу VseGPT. Если кадр выйдет «рисованным» — это не поломка,
  а свойство модели; тогда YandexART остаётся дешёвым черновым каналом, а премиум берём на VseGPT.
- **~2₽/карточка** (из памяти `yandexart-cheapest-rf-image-channel`, плоская оценка в коде
  `YAART_EST_USD = 0.0176`, точный факт — в биллинге кабинета: у операции нет поля usage).
- Роль сервисного аккаунта **установлена**: `ai.imageGeneration.user` (шаг 1).

## Когда вернёмся к VseGPT (премиум-плечо)

Продлить Проф (399₽/30д) + пополнить баланс на `vsegpt.ru` → разморозка аккаунта.
Всё премиум-плечо **уже в нашем ключе**, покупать модели не надо:

| модель | ₽/кадр | чем берёт |
|---|---|---|
| `img-openai/gpt-image-2` | 10.0 | лучший текст на картинке (ChatGPT Images 2.0) |
| `img-google/nano-banana-2` | 19.9 | середина |
| `img-google/nano-banana-pro` | 29.9 | топ-качество |
| `img-flux/flux-2-klein-4b` | 3.9 | текущий дешёвый (текст не умеет) |
| `img2img/*-edit` (`kontext-pro-edit` 7.5) | 7.5 | **правка донора — ветка не задействована** |

Переключение канала = одна строка `PHOTO_FORGE_PROVIDER` + `RU_OPENAI_MODEL` в `.env`.

Проверить баланс: `v1/balance` на нашем ключе **выключен** и врёт HTTP 200 с ошибкой внутри —
читать глазами на `vsegpt.ru/User/Money`. Факт заморозки виден иначе: доктор ловит её
0₽-зондом (generate-запрос с несуществующим слагом: шлюз проверяет заморозку раньше модели).
