> Построено 2026-09-08 зеркалом ЯМ-линии (шаблоны: `ymarket_day/cycle_day/autopilot/console`),
> НО под ОЗОН: один кабинет (client 5162853), день и есть движок (мульти-стор не нужен).
> Приёмки: **31/31 зелёных** (день 9/9 · цикл-день 8/8 · автопилот 6/6 · консоль 8/8) + канон.
> `ymarket_*` НЕ трогали (регрессия ЯМ зелёная, см. конец).

**Назначение**: ОЗОН становится само-идущей линией как ЯМ — суточный день докладывает
(`ozon_day`), реестр заданий ведётся через ОБЩИЙ реестр `ymarket_tasks_v1` (маркет `ozon`),
рука под расписанием крутит день сухо (`ozon_autopilot` + launchd), а read-кабинет показывает
всё одним листом (`ozon_console`). МОЗГ-REPL (`ozon_brain`) — следующий заход, не здесь.

## Роли (4 новых модуля)

| Модуль | Роль | Что делает | Законы |
|--------|------|------------|--------|
| `ozon_day_v1.py` | **СУТОЧНЫЙ ДЕНЬ** | один день органа: тик УПРАВЛЯЮЩЕГО → само-модель → 6 ОТДЕЛОВ (0₽ на памяти) → дознание кабинета (0₽ READ, если `live_read`) → KPI + дельта ко вчера → что горит → журнал | D1–D9 |
| `ozon_cycle_day_v1.py` | **ДИСПЕТЧЕР ЗАДАНИЙ** | наблюдения из памяти карточек + журнала дня (evidence = артефакт) → сев в ОБЩИЙ реестр (`market="ozon"`, cycle `cycle_day`) → планёрка → сухой подхват дня по открытым | C1–C8 (CD1–CD6) |
| `ozon_autopilot_v1.py` | **РУКА ПОД РАСПИСАНИЕ** | `run()` = `day.run_day(dry=True, live_read=True)` (0₽ GET дознание) + человеко/JSON-лог, ротация >2МБ, fail-soft exit 0 | A1–A6 |
| `ozon_console_v1.py` | **READ-КАБИНЕТ** | pure-read пульт: ШТАБ · ДЕНЬ · KPI · ОТДЕЛЫ · ЗАДАНИЯ · ДОЗНАНИЕ · АВТО · ДЕЛО — ничего не пишет, сеть не зовёт, ANSI только на живом tty | CC1–CC11 |

## Entrypoints (все сухие, 0₽; живьё-по-слову)

```
# день (dry по умолчанию; --live-read включает 0₽ дознание кабинета; env OZON_LIVE=1 тоже)
python3 ozon_day_v1.py --dry [--live-read] [--json]

# диспетчер заданий: планёрка / форма / форма с записью в реестр / разбор + сухой день
python3 ozon_cycle_day_v1.py --plannerka
python3 ozon_cycle_day_v1.py --form [--commit]        # --commit — единственный write (реестр, не сеть)
python3 ozon_cycle_day_v1.py --dispatch [--cycle-dry] # --cycle-dry подхватывает день СУХО

# автопилот (одна строка; --json — машинный; лог в MEMORY_WAVE/.../ozon_autopilot.log)
python3 ozon_autopilot_v1.py [--no-live-read] [--json]

# консоль: read-кабинет (пайп/скрипт = plain, tty = цвет)
python3 ozon_console_v1.py --штаб | --день | --kpi | --отделы [--роль X] | --задания | --дознание | --авто | --дело

# launchd (СОЗДАН, НЕ загружен без слова оператора)
cp com.wavy.socc.ozon_autopilot.plist ~/Library/LaunchAgents/
launchctl load  ~/Library/LaunchAgents/com.wavy.socc.ozon_autopilot.plist
launchctl kickstart gui/$(id -u)/com.wavy.socc.ozon_autopilot
```

## Ключевые законы (зашиты механически, тесты = стража)

- **RUBICON физически**: у `ozon_day.run_day` НЕТ параметра commit (день всегда `commit=False`);
  у `ozon_autopilot.run` НЕТ пути к живому дню (строго `dry=True`). Реальный write Озона закрыт
  до **ротации ключа** (скомпрометирован 06.08) + слова оператора.
- **B2**: падение отдела/дознания/тика НЕ роняет день — провал честно в `failures`, день `ok=False`
  (не врёт «продаж N», если живой факт недостижим).
- **CD2 evidence**: наблюдение без артефакта не формируется (пустое evidence → кандидата нет).
- **CD5 без фейк-пасс**: диспетчер подхватывает день сухо ТОЛЬКО с явным `--cycle-dry`, сам
  `mark_step` не делает никогда.
- **CD6 единственный write диспетчера** — локальный общий реестр задач (не сеть).
- **CC честность пустоты**: «журнала дня нет» ≠ «слепка ещё нет» ≠ «реестра ещё нет» ≠ «0 открытых».
- **Реестр ОБЩИЙ**: `ymarket_tasks_v1` переиспользован без изменений; ОЗОН пишет/читает через
  `market="ozon"` (`MARKETS = ("ym","ozon")`); чужие записи форма не трогает (дедуп по TZ1-id).
- **CLI дня всегда сухой**: найден и исправлен баг приёмки — `--dry` с `default=True` и
  `dry=not args.dry` давал «живой» отчёт. Теперь `run_day(dry=True)` константой (D5 страхует).
