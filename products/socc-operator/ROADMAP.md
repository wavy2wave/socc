# SOCC Operator · Roadmap

## Принцип

Каждая ступень обязана:

1. опираться на существующее ядро;
2. производить измеримый результат;
3. закрываться proof;
4. не расширять риск без Trust Ladder.

## Stage 0 · Product Skeleton — сейчас

- канон продукта;
- карта связи с SOCC OS;
- метрики;
- приёмка структуры.

## Stage 1 · Read Operator

- единый срез состояния;
- отчёт «что горит»;
- evidence для каждой проблемы;
- CLI-пульт.

Результат: клиент утром видит состояние дела.

## Stage 2 · Control Room

- очередь задач;
- план действий;
- dry-preview;
- статусы, proof, история.

Результат: оператор управляет делом из одного места.

## Stage 3 · Safe Actions

- безопасные исправления;
- автоматизация повторяющихся задач;
- Trust Ladder;
- подтверждение для опасных действий.

Результат: рутина уходит из рук оператора.

## Stage 4 · Learning Operator

- Outcome Memory;
- селектор на опыте;
- снижение cost per operation;
- повторное использование успешных путей.

Результат: каждый цикл дешевле и быстрее.

## Stage 5 · Multi-vertical Operator

- маркетплейсы;
- клиники;
- сервисы;
- новые вертикали как пакеты.

Результат: SOCC OS масштабируется через продукты.
