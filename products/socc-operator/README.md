# SOCC Operator · Операционный контур для ведения дел

> **SOCC Operator — это первый продукто-вход в SOCC OS.**
> Он не заменяет ядро и не дублирует `scripts/mint/arbiter`.
> Он связывает существующие органы SOCC в одну продуктовую петлю:

```
CONNECT → OBSERVE → FIND → PLAN → PREVIEW → EXECUTE → PROVE → REPORT → REMEMBER
```

## Зачем эта папка

Текущее ядро уже умеет:

- читать состояние маркетплейсов и клиник;
- формировать задания;
- прогонять циклы dry/commit;
- писать proof;
- вести память;
- рождать сущности.

Но клиент не покупает «ядро». Клиент покупает **результат**:

- что сломано;
- что сделать;
- что уже сделано;
- что доказано;
- сколько это стоило/сэкономило.

`products/socc-operator` — это место, где ядро становится продуктом.

## Что входит

| слой | смысл |
|---|---|
| `PRODUCT.md` | канон продукта: пользователь, боль, результат, границы |
| `ARCHITECTURE.md` | связь с SOCC OS: state, selector, action, proof, memory |
| `METRICS.md` | язык ценности: часы, деньги, ошибки, скорость |
| `ROADMAP.md` | ступени: Audit → Control Room → Safe Actions → Operator |
| `acceptance/` | гейты и приёмки продукта |
| `runtime/` | будущая продуктовая сборка (не живые данные) |
| `ui/` | будущий пульт оператора |

## Закон границы

- ядро SOCC не переписывается под продукт;
- продукт использует SOCC как платформу;
- живые данные клиентов — вне git (M3);
- любые внешние действия — через RUBICON;
- каждый значимый шаг — proof.
