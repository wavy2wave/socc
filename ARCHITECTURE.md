# SOCC · Архитектура машины

> SOCC — **операционная система для будущих продуктов** (SOCC OS):
> живое суверенное ядро, которое держит закон, память, самостройку,
> рождает сущности и ведёт продукты. Не «бот» и не «набор скриптов»,
> а ОС с проверяемым циклом: состояние → выбор → действие → proof →
> память → следующий шаг.

SOCC OS — не фабрика однотипных дел. Это **базовое ПО** оператора:
общие ядро, механика, память, дизайн и артефакт-слой для любых продуктов —
маркетплейс-циклы, ANNA, платформы, сервисы, будущие задумки.

## Главный принцип: подводная лодка

Ошибки возможны. Незаметных ошибок — нет.

- **Отсеки.** Ядро, фабрика сущностей, продукты и данные разделены физически.
- **Двери.** Каждый write закрыт RUBICON: `--dry` по умолчанию, `--commit` только оператором.
- **Контроль затопления.** FAIL останавливает цепь, не топит машину. Причина фиксируется в леджере.
- **Эволюция вместо смерти.** Ошибка становится опытом: proof → memory → selector.

Система не обязана быть идеальной. Она обязана быть **проверяемой и ремонтопригодной**.

## Жизненный контур ядра

```
STATE      → что реально есть сейчас (файлы, задачи, продукты, сущности)
SELECTOR   → кандидаты задач из состояния
CRITIC     → не фантик? real effect? не ломает закон?
EFFECT GATE→ один шаг с измеримым БЫЛО → СТАЛО
EXECUTION  → bounded, dry по умолчанию, commit = RUBICON
VALIDATOR  → проверяет артефакт, не текст
PROOF      → immutable evidence в proof-chain
MEMORY     → причинность: действие → эффект → выбор
NEXT       → lawful_next, следующий законный шаг
```

## Рождение продукта

```
задача оператора
    ↓
домен-конфиг (entity_substrate/domains/)
    ↓
ENTITY FORGE (--dry → --commit)
    ↓
сущность: 10 поверхностей
    ↓
бounded запуск в продукте
    ↓
proof + memory + метрики
    ↓
ядро усиливается
```

Продукт не копирует ядро. Продукт **рождается** через Entity Substrate
и живёт на ядре, как отдельный организм с пуповиной.

## SOCC OS · продукты как приложения

```
wavy / operator
        ↓ intent
SOCC OS (ядро + память + артефакты + канон)
        ↓
PRODUCTS = applications
   YM CYCLE · OZON CYCLE · ANNA · платформа ретрансляции · новые задумки
```

Продукт — не копия ядра и не «ветка». Продукт = приложение на SOCC OS:
- использует общий движок, proof, RUBICON, память;
- наследует механики и визуальный канон;
- получает собственные домен, каналы, метрики, деньги;
- возвращает опыт и артефакты обратно в ОС.

## Artifact Intake · лут → актив

Оператор собирает артефакты всюду: чаты, YouTube, файлы, транскрипты,
рынок, код, старые проекты. Это не мусор — сырьё для SOCC OS. Но
**сырьё не равно канон**.

```
ARTIFACT (сырой: диалог, идея, схема, код, паттерн, рыночный сигнал)
    ↓ CAPTURE        собрать и сохранить источник/контекст
    ↓ TRIAGE         что это: идея / паттерн / закон / дизайн / поставщик / дефект
    ↓ DEDUPE         не плодить дубли, сверять с канон-узлами
    ↓ CANONIZE       извлечь reusable ядро
    ↓ ROUTE          куда: product backlog / capability / design-canon / memory
    ↓ USE            артефакт реально влияет на продукт/ядро
    ↓ PROOF          зафиксировать эффект использования
```

Правила:
- сырой лут — вне git (M3), канонизированные артефакты — в git;
- каждый канон-артефакт имеет источник, статус и применение;
- артефакт без использования — склад, не актив;
- артефакт с proof-эффектом — актив SOCC OS.

## Семейство продуктов

Все продукты SOCC узнаваемы как одно семейство:

| слой | наследуется от SOCC OS |
|---|---|
| механика | proof, RUBICON, dry/commit, bounded actions |
| характер | спокойная точность, честный PASS/FAIL, без хайпа |
| визуал | канонический design-tokens, типографика, тон |
| интерфейс | пульт, леджер, статус, lawful_next |
| память | общая Memory Wave и опыт |

## Cycle Engine · общий движок дела

YM и Ozon — не два разных мира, а инстансы одного цикла:

```
идея → сборка → канал/витрина → продажа → доставка → деньги
     → сверка → планёрка → новая итерация
```

`marketplace pack` = адаптер ЯМ/Ozon. Следующие способности:

- **EXECUTION MODE** — гарантированное исполнение задания (сейчас);
- **SEARCH MODE** — цикл сам ищет вариации товаров, схемы, каналы и идет к цели;
- **EVOLUTION MODE** — успешные пробы масштабируются, провалы пишутся в память.
