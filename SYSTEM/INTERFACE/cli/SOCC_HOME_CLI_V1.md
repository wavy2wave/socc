# SOCC · ДОМ — единый CLI-вход системы (SOCC_HOME_CLI_V1)

> Оператор: «Создай лучший дом для ЦИКЛА ЯМ. Учти: такой же CLI вход есть и у SOCC — там я могу
> открыть OZON CYCLE, CYCLE YM, ENTITY SUBSTRATE, или Анну. ЯМ-цикл не существует сам по себе.
> Канонический дизайн и интерфейс нашей системы — важно.» — ДОМ это один вход во все органы:
> **открыть/смотреть** всю систему, не влиять (read 0₽).

**Движок-канон**: `socc_cli.home` (одна правда интерфейса). Два тождественных входа зовут один
диспетчер: `socc home|ym|ozon|substrate|anna|kernel` (канонный CLI) и `CYCLE` (фирменный алиас
оператора, симлинк `~/.npm-global/bin/CYCLE` → `scripts/mint/arbiter/CYCLE`). Цвета/типографика —
`socc_cli.style` (CC8: ANSI на живом tty, plain в пайпе/StringIO).

## Команды

| вход | что открывает |
|---|---|
| `socc home` / `CYCLE` | дашборд: 6 органов-карточек (КЕРНЕЛЬ·ЯМ·OZON·SUBSTRATE·ANNA·MIGRATION) с честной сигнатурой + входы + правила |
| `socc ym [дело\|планёрка\|задания\|штаб\|день\|kpi\|артефакты\|авто\|мозг]` | ЯМ-ЦИКЛ глубоко (агрегирует `ymarket_console_v1`+`cycle_day` в процессе) |
| `socc ozon` | OZON-менеджер: read-карточка последнего тика |
| `socc substrate` | ENTITY SUBSTRATE: принятое направление + домены |
| `socc anna` | ANNA: направление MVP · L2-кандидат · дашборд 8790 |
| `socc kernel` | КЕРНЕЛЬ: route authority (lawful_next) |
| `socc migrate` | MIGRATION · LINE_MIGRATOR: переноска кода → GitHub/VPS · безопасность (read-лицо) |
| `socc задания` | ЗАДАНИЯ — весь реестр систем (топливо ДОМА, 0₽) |
| `socc ym мозг` | интерактивный МОЗГ (навигатор, read-REPL) |

`CYCLE YM <под>` ≡ `socc ym <под>` — один движок. `CYCLE` без аргументов = `socc home`.

## Интерактив (живой дом, `socc_cli.dom`)

На **живом терминале** входы открывают не «кирпич-текст», а меню-навигацию (движок `dom.py`,
аддитивный слой над `home`, те же render-хелперы/типографика/CC8). Интерфейс построен на
**движке стабильного viewport** (`socc_cli/view.py`), который устранил «плывущие» кадры:
один alt-screen на виджет · автоперенос выключен · каждый кадр = ровно ROWS строк, каждый ряд
адресуется абсолютно `\x1b[{r};1H` + затирание хвоста `\x1b[K` · **внутри кадра нет `\n`** ·
геометрия постоянна (шапка 4+1 · низ 3 → тело всегда rows−8) · обрезка по клеткам ширины без
разрезания ANSI. Низ (3 строки) всегда прижат: инфо · подробность/таймер · подсказка.

- `socc home` → меню органов; `socc ym` → **ДОМ ЯМ-ЦИКЛА**: сам себя объясняет —
  «ЯМ-ЦИКЛ: донор → сборка → залив → витрина → учёт → сверка · цикл дня идёт сам ·
  <тики>»; КАМПАНИИ по номерам, у каждой хеш цикла 10 (`sha1(slug×дата×цепь)`) →
  выбрать кампанию → её **АКТИВНЫЕ ЗАДАНИЯ** + пульс + ЦИКЛ СЕГОДНЯ (леджер растёт —
  живой след);
- кампания = **ДОМ ЯМ-ЦИКЛ <хеш>** — один сводный кадр из шести секций
  (ПУЛЬС · ЦИКЛ СЕГОДНЯ · ЦИКЛЫ В РАБОТЕ · АКТИВНЫЕ ЗАДАНИЯ · ГЕЙТ ЦИКЛ-1 ·
  РЕЗУЛЬТАТ ДНЯ); честно: «◌ цикл дня идёт сам» по расписанию (маркера «завершён»
  в данных нет — не врём); ДЕЙСТВИЯ прижаты книзу (**ЖИВОЙ · ГЕЙТ ЦИКЛ-1 · АВТО ·
  ЗАДАНИЯ · НАЗАД**);
- **ГЕЙТ ЦИКЛ-1** = честная read-сводка условий (манифест 8 полей · категория ·
  адрес витрины · builder/маржа/остаток · витрина PUBLISHED · остатки) + кто запускает
  (**БРИГАДИР**: `ymarket_cycle1_v1 --dry` 0₽ · `--commit` по слову оператора RUBICON);
  из ДОМА движок НЕ запускается — только смотрит и зовёт исполнителя;
- витрина = **экран-чтение (READOUT)**: тело листается ↑↓ по страницам, **ДЕЙСТВИЯ прижаты
  книзу** и всегда видны; подпись «АКТИВНЫЕ ЗАДАНИЯ · N · роли» — в нижней строке даже когда
  тело ушло под сгиб на малом экране;
- `socc ym <витрина>` → сразу витрина (tty) или один-экран текст (пайп);
- **ТОПЛИВО** — в меню ДОМА секция `📋 ЗАДАНИЯ · весь реестр систем` (врезка
  `tasks:home`); отдельно — top-level `socc задания` (§ЗАДАНИЯ);
- **[1] ЖИВОЙ ЭКРАН** — автообновление каждые 2с: тело якорено **к низу** (свежий ход на
  последней строке), таймер автопилота в нижней строке («процессы идут — и я вижу это»);
- управление: `↑↓`/`j k` — листать/выбрать · цифра — действие сразу · `q` — **назад на
  ОДНУ ступень** (у ДОМА `q` — выход). Вложенность: дом → ЯМ → витрина → (live/под-экраны).

В пайпе/StringIO/`--text` — прежний один-экран текст (HH2 не ломаем). `socc` без аргументов —
по-прежнему `observe`.

### ПУЛЬТ — исполнитель ДОМА (`socc_cli/pult.py`)

Оператор: «строим именно CLI интерфейс, который И ЕСТЬ наша система. Не просто обёртка,
а ЖИВОЙ ПУЛЬТ управления. Доработай до проф. уровня». ПУЛЬТ закрывает разрыв «ДОМ только
смотрит»: из ДОМА кампании он единственный запускает НАСТОЯЩИЙ движок ЦИКЛ-1 **тем же argv,
что БРИГАДИР** (`python3 scripts/mint/arbiter/ymarket_cycle1_v1.py --store <slug> --dry|--commit`,
cwd=SOCC, timeout 300). Входы: `run_fleet` (ПУЛЬТ · ШТАБ — весь флот по правилу хода
КОМАНДИРА ДНЯ) и `run_store_pult` (КОМАНДИР ДНЯ одной витрины). Из меню ДОМА пульт зовётся
ленивым импортом (без цикла на уровне модуля); старый ЖИВОЙ ЭКРАН `dom._live` не тронут —
ПУЛЬТ-ШТАБ рядом.

**Закон разделения**: `dom.py` остаётся ЧИСТЫМ (DH8 — смотрит и зовёт), `pult.py` —
ЕДИНСТВЕННЫЙ исполнитель ДОМА (subprocess — только в `_exec_cycle`, и только настоящего
движка). Сам пульт файлы НЕ пишет — пишет движок под словом оператора.

**Рельс исполнения (вилки оператора)**: сухой прогон `d` — одно подтверждение (Enter);
живой `c` — RUBICON, **двойное**: введи слово-магазин (= slug, регистр/пробелы не важны)
+ Enter; Esc/`q` на любой ступени — отмена на ступень назад. После прогона пульт
показывает свежий КОМАНДИР ДНЯ (леджер обновился — видно). В пайпе/StringIO пульт только
смотрит: печатает плоский ШТАБ/КОМАНДИР и возвращает `'back'` — движок не стартует.

**Деньги ЧЕСТНО** (`_money_txt`/`_fleet_money_line`): закуп → потенциал ×маржа · PUBLISHED-арт
(из СВЕРКА-PASS) · подпись «0₽ реальных», пока в леджере нет строки `dry:false`; живая
строка → «живых строк N» (не врём «заработано»). Канон отчётов ARBITER — только repo-root
`MEMORY_WAVE/reports/mint/arbiter`.

### ЭКОСИСТЕМА — навигатор магазина (`socc_cli/eco.py`)

Лицо магазина внутри ДОМА: read-дрилл (0₽, движок не зовётся) по эко-разделам витрины на
честных данных, что уже лежат. Кнопка **ЭКО** в ДЕЙСТВИЯХ магазина (tty) / строка
`ЭКОСИСТЕМА · разделы магазина` (пайп) → кадр `ЭКОСИСТЕМА · <slug>` с хешем дня
`sha1(slug|дата|film-1.0)[:10]` (как DH13 — одно лицо дня). Разделы — **в порядке оператора**:

1. **ЗАДАНИЯ** — реестр durable (`ymarket_tasks.json`) если материализован + живая очередь
   наблюдений из сторов; файла нет → честно «реестр не материализован» (резерв: придёт с ЦИКЛ-ДЕНЬ).
2. **ЦИКЛЫ** — прогоны леджера; провал в прогон = **ЦИКЛ · отчёт прогона** (логи узлов
   `HH:MM ✓/◌/✗ сухо|ЖИВОЙ` + evidence-стрелки `→ ARB-… PUBLISHED · остаток` + закрытие ПЛАНЁРКОЙ).
3. **СОТРУДНИКИ** — активные владельцы (дневной пул по ролям): имя · занят what · задач/наблюдений;
   провал в роль = её задачи+наблюдения в этом магазине.
4. **ДОНОР** — карточка (категория · builder/маржа/остаток) + артефакты разведки (glob файлов).
5. **АРТЕФАКТЫ** — витрина PUBLISHED (evidence СВЕРКА) · собранные карточки матрицы · карты закупа ·
   закрытые/в работе · честный резерв «процента выполнения» (пока реестра нет).

Футер-резерв «ЗАКАЗЫ и другие — проектируется» — в плоском листе (tty-навигатор = pick:
секции + «Назад к ДОМУ»). Ничего не выдумываем: данные читаются из `store_payload` на каждый
вход; пустые сущности — честные строки, не нули. Дрилл аддитивен: кадр `ДОМ ЯМ-ЦИКЛ <хеш>`
и DH-секции не тронуты; дом-слой движок не запускает (eco.py чист, EC9).

Клавиши навигатора: `↑↓`/`j k` — листать секции · цифра/Enter — провал в раздел ·
`q`/Esc — на ступень назад. Провалы-экраны — отдельные alt-кадры (пауза `_show_pause` /
вложенный pick), `q` всегда возвращает на одну ступень выше.

Приёмка герметичная (payload-инъекция, движок не стартует, 0₽, леджер цел):
`python3 scripts/socc/socc_dom_eco_acceptance_v1.py` → EC1–EC12 12/12 PASS. Живой дым raw-клавиш
на настоящем pty поверх реального `socc` (движок ни разу не зовётся): `python3 scripts/socc/
socc_dom_eco_pty_smoke_v1.py` → E1 навигатор_вход ✅ · E2 провал_задания_и_циклы (→ отчёт
прогона) ✅ · E3 стабильный_кадр_80×24 ✅ (на РОВНО 80×24: навигатор → ЗАДАНИЯ → ЦИКЛЫ →
отчёт прогона — каждый кадр с низом `\x1b[24;1H`, без `\n` внутри, за 24-й ряд не лезет;
та же планка СТАБИЛЬНОГО КАДРА, что у дом-дымов S1–S3 и пульта P3). Цифры (магазин/кнопка
ЭКО/секции) считаются динамически из `ym_rows`/исходника dom/`eco._SECTIONS`, не
хардкодятся. Экран секций/отчётов гоняет реальный леджер витрины — сценарии ждут текст в
порядке отрисовки кадра (сверху вниз), без хардкода данных.

### ЗАДАНИЯ — топливо ДОМА (`socc_cli/tasks.py`)

Оператор: «ЗАДАНИЯ — топливо для системы … строим CLI … сразу внутри моего кли дома
реализовано». ЗАДАНИЯ — **первое-класс лицо ДОМА на уровне home**: top-level `socc задания`
в пайпе → плоская планёрка всех открытых; на живом терминале → меню-реестр (строки по
важности, нумерация глобальная по заданиям, окно листает) → провал цифрой = КАРТОЧКА
задания (пункты ●/○ + evidence, `render_task` органа). В меню ДОМА — секция **ТОПЛИВО →
📋 ЗАДАНИЯ · весь реестр систем** (врезка `tasks:home` из home_rows, ленивый импорт, дом
остаётся DH8-чистым). До этого реестр был виден только внутри ЯМ (`socc ym задания` /
экран магазина) — теперь это лицо ДОМА (глобально, все маркеты/магазины).

**Данные — ОДНА правда**: читаем СТОР реестра и сортируем/фильтруем/считаем функциями
органа `ymarket_tasks_v1` (task_path/load/open_only/sort_tasks/stats/derive/render_task) —
логику не пере-реализуем. env `YM_TASKS_PATH` уважается органом → тесты герметичны (tmp),
канон-стор не трогается. Лицо **не пишет и движок не зовёт** (как eco/pult: чистый
read-слой поверх dom; RUBICON цел — живая запись реестра только form/seed/движок по слову
оператора).

**Выход-код**: `run_tasks` — корневое лицо dispatch (как run_home/run_ym): выход из
корневого меню ЗАДАНИЯ → **0** (dispatch `_rc0` → чистый exit 0 на `socc задания`); внутри
`run_home` return игнорируется (врезка `tasks:home` → continue). Регресс «"back" улетал в
`sys.exit("back")` = код 1» — пойман и засторожен в живом дыме T1 (rc 0 обязателен).

| # | закон | как исполняется |
|---|---|---|
| TX1 | лицо_плоское | `tasks_text` на StringIO без ANSI (CC8) · банд `ЗАДАНИЯ · ДОМ` · группы-магазины с «открыто N» · строки с id · владельцем · пунктами X/Y |
| TX2 | честный_tri_state | орган-не-импорт / стора-нет / битый → честная строка, не фейк-пусто (CD1) |
| TX3 | сводка_честна | записей · закрыто % · в работе · ждут · срочных; закрытое (derive done) в строки НЕ идёт, в сводке честно |
| TX4 | важное_выше | порядок строк = sort_tasks органа (priority → срочность → created_at): P10 над P20, срочное над normal — как планёрка цикла |
| TX5 | карточка_пункты | render_task: what [state·id] · пункты ● (evidence) / ○ · длинное режется ≤78 |

Клавиши лица: `↑↓`/`j k` — листать/выбрать · цифра/Enter — карточка задания · `q`/Esc —
на ступень назад (из карточки — к реестру, из реестра — в ДОМ / выход). Нумеруются только
задания (текст/сеп-строки не считаются) — цифра 1 = первая открытая по важности
(sort_tasks органа).

Приёмка герметичная (инъекция/мононе-патч, движок не стартует, 0₽, канон-стор байт-в-байт):
`python3 scripts/socc/socc_dom_tasks_acceptance_v1.py` → TX1–TX8 8/8 PASS. Живой дым raw-клавиш

## АГЕНТ — живой экран «система работает перед тобой» (`socc_cli/agent.py`)

Оператор: «сделай интерфейс как у Claude Code, где система реально работает (думает),
весь интерфейс как у Claude». АГЕНТ — строка ввода, а система видимо «думает» и
по-настоящему делает: **сухой прогон ЦИКЛ-1** (движок, `--dry`, 0₽, узлы льются живым
потоком) и **ответы из реального стора**. Вход: `socc агент` (≡ `python3 -m socc_cli.agent`).
Фразы: «прогон/цикл/запусти» → сухой прогон ЦИКЛ-1 · «статус/итог» → сводка магазина
(лежер·пульс·очередь·реестр-честно) · «полка/витрина» → PUBLISHED-артефакты (evidence) ·
«что умеешь» → помощь · «выход» → конец. Живое слово («commit», «в бой») → честный отказ
(RUBICON цел: движок зовётся ТОЛЬКО `--dry`).

**Почему АГЕНТ не «плывёт»**: он живёт в ОБЫЧНОМ терминале (cooked, scrollback), а не в
сыром кадре — каждая строка печатается один раз, перенос/прокрутку делает сам терминал,
съезжать физически нечему. Это второе правило стабильности рядом с кадровым (view.py):
**кадр** — для меню-экранов дом/пульт/эко (alt-screen, CUP, без `\n`), **лента** — для
АГЕНТА (живой поток, без сырых кадров). На живом терминале авторские строки режутся до
ширины экрана (`view.clip_ansi`), в пайпе — НЕ режутся (терминала нет, нечему переноситься).

| # | закон | как исполняется |
|---|---|---|
| AG1 | лента_честная | живой tty: каждая авторская строка ≤ ширины (clip_ansi, ANSI не режет); пайп — строки целыми; ничего не врём (вердикты настоящие) |
| AG2 | сухо_по_умолчанию | движок зовётся ТОЛЬКО `--dry` (argv как БРИГАДИР); «живой/commit/в бой» → отказ + подсказка (RUBICON) |
| AG3 | реальные_вердикты | ответы = настоящий стора (`store_payload`) и настоящий вывод движка (rc); пусто → честная строка, не краш |
| AG4 | вход_не_падает | манифест пуст → честно; «выход» → rc 0; Ctrl+C → чистое «до встречи»; движок-поток Ctrl+C → terminate |

Приёмка (герметичная, движок не стартует): `scripts/socc/socc_cli_agent_acceptance_v1.py`
AG1–AG4. Живой пример: `socc агент`, затем «статус» / «прогон» (реальный движок, ~1 мин).

## Правила системы

- **0₽ read**: ДОМ ничего не пишет и сеть не зовёт. Живые действия (--commit · создать ·
  цикл-диспетч) живут в органах-исполнителях и открываются только по слову оператора (RUBICON).
- **Исполнитель — пульт**: внутри ДОМА живой `--commit` запускается ТОЛЬКО с пульта
  (pult.py) по двойному подтверждению (слово-магазин = RUBICON); движок ЦИКЛ-1 пишет на
  витрину сам, пульт файлов не трогает. Дом-слой (home/dom) никогда не запускает движок.
- **Не ломать**: `socc` без аргументов остаётся `observe` (маршрут КЕРНЕЛЯ) — хаб добавлен
  аддитивно. Все входы КОНСОЛЬ-ЯМ (`ymarket_console_v1.py --…`) и `CYCLE <под>` продолжают работать.
- **Один вход, много лиц**: страницы-лица (ym/ozon/substrate/anna/kernel) читают сторы напрямую
  (fail-soft, честная пустота), глубокие лица зовут read-органы в процессе.
